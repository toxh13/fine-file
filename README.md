# fine-file

폴더 크기가 보이고, 입력하는 즉시 찾아지는 Windows 파일 탐색기.

- **폴더 크기 열**: 모든 폴더 옆에 용량과 파일 수가 바로 보여요.
- **고속 스캔**: NTFS 드라이브는 MFT(파일 목록표)를 직접 읽어서 수 초 안에 끝나요. 관리자 권한이 필요하면 UAC 창으로 허락을 받고, 거절하면 일반 권한 탐색으로 대신해요. 드라이브마다 처음 한 번이면 돼요.
- **빠른 동기화**: 스캔한 드라이브의 버튼은 "동기화"예요. 관리자 권한 없이(UAC 창 없이) 폴더를 다시 훑어 지금 디스크에 맞추고, 내 계정으로 열 수 없는 폴더는 마지막 스캔 내용을 그대로 써요. 앱을 켤 때(꺼 둔 동안 바뀐 것)와 실시간 반영이 변경을 놓쳤을 때는 저절로 돌아요 (아래 "스캔 방식").
- **실시간 반영**: 스캔한 로컬 드라이브는 파일이 생기고, 지워지고, 바뀌는 대로 폴더 크기와 검색 결과에 반영돼요. 관리자 권한 없이 일반 권한으로 동작해요.
- **즉시 검색**: 모든 드라이브의 파일 이름을 메모리에서 찾아요. 띄어쓰기로 여러 단어(AND), `*`·`?` 와일드카드를 쓸 수 있어요.
- **탭**: 탭마다 폴더, 뒤로/앞으로 기록, 보기 방식, 검색, 선택, 트리에서 펼친 폴더를 따로 가져요. 폴더를 가운데 클릭하면 새 탭으로 뒤에서 열리고, 메뉴의 "새 탭에서 열기"는 그 탭으로 바로 가요. 열어 둔 탭은 다음에 켤 때 그대로 돌아와요. 그 사이 없어진 폴더는 남아 있는 가장 가까운 위 폴더로 열어요.
- **즐겨찾기 (왼쪽 바로 가기)**: Windows 탐색기의 왼쪽 창처럼, 같은 순서로 홈과 원드라이브(개인용 "OneDrive - Personal", 회사·학교용 "OneDrive - 조직 이름"), 줄 아래에 바탕 화면, 다운로드, 문서, 사진, 음악, 동영상(Windows가 정해 둔 위치라 원드라이브로 옮긴 폴더도 맞게 찾고, 이름과 아이콘도 Windows의 것이에요), 그 아래에 내가 고정한 폴더(핀 아이콘)가 보여요. 폴더(목록·트리·아이콘·검색 결과)를 오른쪽 클릭 → "즐겨찾기에 고정"하거나, 폴더를 끌어 즐겨찾기의 줄과 줄 사이(파란 선)·즐겨찾기 머리·맨 아래 빈 곳에 놓으면 그 자리에 고정돼요(줄의 가운데에 놓으면 지금처럼 그 폴더로 복사돼요). 고정한 폴더는 끌어서, 또는 Alt+↑/↓로 순서를 바꿔요. 즐겨찾기의 줄을 오른쪽 클릭하면 새 탭에서 열기, 고정 해제(바탕 화면 같은 장소는 "숨기기"), 이름 바꾸기(F2, 즐겨찾기에 보이는 이름만), 탐색기에서 보기, 경로 복사가 있고, 가운데 클릭은 새 탭이에요. 즐겨찾기 머리의 "⋯"에는 "탐색기 즐겨찾기 가져오기"(탐색기의 빠른 액세스에 고정한 폴더 중 여기에 없는 것. 처음 켤 때 한 번 물어요), "지금 폴더 고정", "숨긴 장소 다시 보이기"가 있어요. 지워졌거나 빠진 드라이브의 폴더는 흐리게 "폴더를 찾을 수 없어요"로 보이고 옆에 "고정 해제"가 있어요. 즐겨찾기·드라이브·도구는 머리를 눌러 접고 펼칠 수 있어요. 고정한 폴더(100개까지, 드라이브 문자가 있는 폴더만. 네트워크 위치는 드라이브 문자로 연결한 뒤 고정해요), 숨긴 장소, 접은 구역은 `%LOCALAPPDATA%\com.toxh13.fine-file\places.json`에 저장돼요. 고정과 숨기기는 이 앱의 왼쪽 창만 바꾸고, 폴더나 탐색기의 즐겨찾기는 바꾸지 않아요.
- **툴바**: Windows 탐색기처럼 두 줄이에요. 첫째 줄은 뒤로·앞으로·위로·새로 고침, 주소창(경로가 길면 지금 폴더 쪽 끝이 보여요), 검색창(안에 "이 폴더만" 스위치)이고, 둘째 줄(명령 모음)은 새 폴더, 잘라내기·복사·붙여넣기·이름 바꾸기·휴지통으로 이동 아이콘, "보기 ▾", 변화, "상세 정보", 그리고 오른쪽에 도구 ▾, AI, 계획, AI 설정(톱니바퀴), 도움말(?)이에요. 아이콘 버튼은 단축키와 똑같이 동작하고, 쓸 수 없을 때(고른 항목이 없을 때, 검색 결과에 붙여넣을 때, 관리자 권한으로 읽는 폴더)는 꺼져서 마우스를 올리면 이유가 보여요. 창이 좁으면(폭 1000픽셀쯤 아래) 변화·위험도·도구·AI·계획이 "⋯"(더 보기) 메뉴로 들어가요. 그래도 버튼이 다 들어가지 않을 때만(글자가 크게 그려질 때처럼) 글자가 빠지고 아이콘만 남고, 그래도 모자라면 잘라내기·복사 같은 아이콘도 "⋯"로 들어가요. 메뉴(보기 ▾, 도구 ▾, ⋯)는 키보드로도 써요(Enter나 Space로 열고, ↑↓로 고르고, Esc로 닫아요).
- **보기 방식**: 목록, 트리, 아이콘(Windows 썸네일), 지도(크기 지도). 툴바 둘째 줄의 "보기 ▾" 메뉴(지금 보기에 ✓)나 Ctrl+Shift+1~4로 바꿔요. 탭마다 따로 기억해요. 검색 결과는 늘 목록으로 보여서 검색하는 동안에는 "보기 ▾"가 쉬어요.
- **크기 지도**: "지도" 보기는 지금 폴더 아래 4단계까지를 크기만큼의 넓이로 그려요. 아이시클·선버스트·트리맵·가지 나무 중에 고를 수 있고, 시스템·프로그램·개발·게임·캐시·미디어·문서·압축·설치·개인·기타로 색이 나뉘어요. 가지 나무는 폴더에서 오른쪽으로 가지를 뻗는 마인드맵이에요(3단계까지, 폴더마다 큰 것 8개와 "기타 N개"). 폴더 블록을 누르면 그 폴더로 들어가고, 맨 위(가운데) 폴더를 누르면 위로 가요. 파일은 두 번 눌러 열어요. 아주 작은 항목은 "기타 N개"로 묶여요. 스캔한 드라이브에서만 그려요.
- **지난 스캔과 비교**: 드라이브를 다시 스캔하면 바로 전 스캔 결과를 하나 남겨 두고, 지금과 비교해 보여 줘요. 빠른 동기화는 남겨 둔 스캔을 바꾸지 않아서, 다음 전체 스캔은 그 전의 전체 스캔과 비교해요(지금 쪽에는 동기화한 결과가 들어가요). 지도 보기의 "변화"를 켜면 늘어난 곳은 빨강, 줄어든 곳은 초록, 새로 생긴 곳은 파랑으로 칠해요. 목록 보기의 "변화" 버튼(탭마다 따로)은 크기 옆에 항목마다 늘거나 준 크기를 보여 주는 열을 더해요. 이 열로 정렬할 수 있고, 위 줄에 비교한 스캔의 시각, 이 폴더 전체의 변화, 없어진 항목이 보여요. 비교는 폴더마다 변화가 큰 64개까지 해서, 그보다 작게 바뀐 항목은 "작음"으로 보여요. 전 스캔이 없으면(처음 스캔했거나, 같은 드라이브 문자에 다른 디스크를 꽂았거나, 디스크 공간이 부족해서 남겨 두지 못했으면) 그 이유와 함께 한 번 더 스캔하라고 알려 줘요. 여기서 스캔은 ▾ 메뉴의 "전체 다시 스캔"(이나 "일반 탐색으로 다시 스캔")이에요. "동기화"는 스캔으로 세지 않아서 몇 번 해도 비교할 스캔이 생기지 않고, 그 알림에도 그렇게 덧붙여요. 실시간 반영은 지금 쪽에만 들어가고, 전 스캔은 다음 스캔까지 그 스캔이 찾은 그대로예요(디스크가 꽉 차서 캐시를 저장할 자리가 모자랄 때만 지워요, 아래 "스캔 방식" 참고). 두 스캔의 방식이 다르면(MFT 고속 스캔과 일반 탐색. MFT 스캔을 동기화한 결과는 열 수 없는 폴더의 내용을 지난 스캔에서 이어받아서 MFT 고속 스캔으로 쳐요) 열 수 없는 폴더가 늘거나 준 것처럼 보일 수 있다고 위 줄에 함께 알려 줘요.
- **Windows 메뉴**: 오른쪽 클릭 메뉴의 "Windows 메뉴 더 보기…", Shift+오른쪽 클릭, Shift+F10, 메뉴 키로 탐색기의 오른쪽 클릭 메뉴를 띄워요. 7-Zip, VS Code, 보내기, 연결 프로그램처럼 다른 프로그램이 넣은 항목도 다 있어요(Shift를 누르고 열면 탐색기처럼 숨은 항목까지). 같은 폴더 안의 항목에만 띄울 수 있어서, 여러 폴더에 걸친 검색 결과에서는 하나만 골라야 해요. 관리자 권한으로 읽는 폴더에서는 띄우지 않아요. 메뉴에서 명령을 고르면 폴더를 다시 읽어요. 탐색기의 "삭제", "이름 바꾸기", "휴지통 비우기"는 이 메뉴에서 빼 두었어요. 탐색기의 삭제는 휴지통이 없거나 꺼진 드라이브의 항목과 휴지통보다 큰 항목을 영구 삭제하고, 휴지통 비우기도 영구 삭제라서예요. 휴지통으로 보내려면 Delete를, 이름을 바꾸려면 F2를 써 주세요(이 앱의 메뉴에도 있어요). **그 밖의 명령은 탐색기와 다른 프로그램의 명령이라 그 규칙대로 동작해요.** 다른 프로그램이 넣은 명령(예: "완전 삭제")은 휴지통을 거치지 않을 수도 있어요.
- **끌어서 놓기**: 목록·아이콘·트리의 항목을 6픽셀쯤 끌면 Windows의 끌어 놓기가 시작돼요. 고른 항목 위에서 끌면 고른 항목 모두를, 아니면 그 항목만 끌어요. 탐색기나 메일·메신저 같은 다른 프로그램에 놓으면 **늘 복사**예요(원본은 그대로 남아요). 네트워크 위치·네트워크 드라이브의 항목, 경로가 256자보다 긴 항목, 이름이 점(.)이나 공백으로 끝나거나 CON·NUL 같은 장치 이름이거나 `?`·`*` 같은 글자가 든 항목은 Windows가 끌어 놓기로 받지 못해서, 끌지 않고 이유를 알려 줘요(복사·잘라내기와 붙여넣기는 돼요). 반대로 탐색기 같은 곳에서 파일을 끌어 와(이 창 안에서 끈 항목도) 폴더 줄·아이콘·트리 줄, 탭, 사이드바의 장소·드라이브에 놓으면 그 폴더로, 그 밖의 빈 곳에 놓으면 지금 폴더로 들어가요. 놓을 곳은 파란 테두리로 보여요. 사이드바 즐겨찾기의 줄과 줄 사이(파란 선)나 즐겨찾기 머리·맨 아래 빈 곳에 놓은 폴더는 복사하지 않고 그 자리에 고정해요(파일은 고정하지 않아요). **이 창 안에서 끈 항목**은 커서에 보이는 대로 복사하고, 놓을 때 Shift를 누르고 있으면 옮겨요(Ctrl도 함께 누르면 복사). 커서에는 Shift를 눌러도 복사(+)로 보여요. 이 창 밖에 놓으면 늘 복사가 되도록 Windows에 복사로만 끌기 때문이에요. 키는 놓는 순간에 누른 것을 봐서, 끄는 도중에 눌러도 돼요. 끈 항목 그대로 다뤄서, 다른 드라이브로 옮긴 폴더(정션)를 끌면 정션이 가리키는 폴더가 아니라 그 정션을 링크 그대로 옮기거나 복사해요. 끈 항목을 제자리(그 항목이 든 폴더, 또는 끈 폴더 자신)에 놓으면 아무것도 하지 않아요. **다른 프로그램에서 끌어 온 항목은 늘 복사**예요(원본은 그대로 남아요). Shift를 눌러도 같아요. 커서에도 복사(+)로 보이기 때문이에요. 옮기려면 잘라내기(Ctrl+X)와 붙여넣기를 써 주세요. 붙여넣기와 같은 작업이라 진행률은 작업 창에 보이고, 이름이 같으면 묻고, 옮기기는 이 앱의 규칙(다른 드라이브면 복사본을 확인한 뒤에만 원본을 지움)을 따라요. 폴더를 그 폴더 안으로 놓을 수는 없고, 검색 결과와 관리자 권한으로 읽는 폴더에는 (그 탭의 머리에도) 놓을 수 없어요.
- **중복 파일 찾기**: 도구 메뉴의 "중복 파일 찾기…"는 지금 폴더(바꿀 수 있어요)에서 내용이 똑같은 파일을 찾아요. 크기가 같은 파일만 고른 뒤, 앞·가운데·끝 부분을 먼저 비교하고 마지막에 파일 전체를 비교해요. 하드 링크는 한 파일로 세고, 원드라이브 같은 클라우드 파일과 온라인 전용 파일은 읽지 않아요(읽으면 내려받게 돼서요). 읽지 않고 건너뛴 파일(스캔한 뒤 바뀌었거나 없어진 파일, 열 수 없는 파일, 온라인 전용 파일)은 결과 위에 개수로 보여 줘요. 찾는 도중에 취소해도 그때까지 내용을 다 비교한 묶음은 보여요. 스캔 결과에 없는 폴더(마지막 스캔 뒤에 생긴 폴더, 다른 드라이브로 옮긴 폴더 같은 링크 폴더)에서는 찾지 않고 이유를 알려 줘요. "최신 하나만 남기기" 같은 자동 선택은 찾은 모든 묶음에서 골라요(화면에는 100묶음씩 보이고 "묶음 더 보기"로 더 펼쳐요. 아래쪽의 선택 개수와 크기는 모든 묶음을 더한 값이에요). 남기는 파일은 Windows 폴더 밖의 파일 중에서 고르고, 휴지통 안에 있는 파일(이미 지운 파일)은 결과에서 빼요(휴지통을 비우면 없어질 사본이 남기는 파일이 되지 않게요). 프로그램·게임·개발 도구·앱 데이터 폴더 안의 파일("프로그램 폴더" 표시)은 자동으로 고르지 않고, "프로그램·앱 데이터 폴더 안 파일도 자동으로 고르기 (주의)"를 켜야 같이 골라요. Windows 폴더 안의 파일은 켜도 고르지 않아요. 그런 파일도 직접 고를 수는 있는데, 휴지통으로 보낼 때는 몇 개가 어느 프로그램 폴더에 있는지(Windows 폴더 안 파일은 따로, 더 강하게) 알려 주고 한 번 더 확인해야 옮겨요. 두 프로그램이 각자 쓰는 같은 파일(모델 등)은 고르지 않은 채로 "하드 링크로 합치기"를 누르면, 자동 선택이 빼 둔 프로그램 폴더 안 파일도 같이 합칠지 물어요(자동 선택 뒤에는 처음부터 켜져 있어요). 묶음마다 적어도 하나는 남기고, 모두 고를 수는 없어요. "위치 보기"를 누르면 창이 닫히고 탭이 그 파일이 든 폴더로 가서 파일을 골라 둬요. 스캔한 드라이브에서만 찾을 수 있어요. 고른 파일은 두 가지로 정리해요.
  - **선택 항목 휴지통으로**: 고른 파일을 휴지통으로 보내요. 정말 필요 없는 사본(두 번 받은 다운로드, 또 복사한 백업)에 써요. 200개씩 나눠 옮기며 진행 상황을 보여 주고, 취소하거나 창을 닫으면 그때 옮기던 200개까지만 옮기고 멈춰요.
  - **하드 링크로 합치기**: 묶음마다 고르지 않은 파일을 남기고, 고른 파일 자리에 그 파일의 NTFS 하드 링크를 만들어요. 두 경로 모두 그대로 열리고 데이터는 한 번만 저장돼서, 두 프로그램이 각자 필요로 하는 같은 파일(두 앱이 따로 받은 AI 모델, 설치 파일)에 알맞아요. 합치기 바로 전에 두 파일이 그대로 있는지(링크나 온라인 전용이 아닌 일반 파일, 같은 NTFS 드라이브, 이미 같은 파일이 아닌지, 찾은 뒤에 크기·날짜가 바뀌지 않았는지, 휴지통이 사본을 받을 수 있는지) 보고, 아무도 쓰지 못하게 연 채로 내용 전체를 다시 읽어 찾을 때의 해시와 비교해서, 하나라도 다르면 건드리지 않아요. 이미 다른 이름(하드 링크)이 있는 사본은 합쳐도 공간이 생기지 않아서 합치지 않고, 합치지 못한 파일로 이유와 함께 알려 줘요(작업 목록에는 "일부 실패"로 보여요). 확인 창은 합칠 파일을 종류별(프로그램 폴더, 문서, 사진·영상·음악 등) 개수로 보여 주고, 고른 파일 중 문서·사진·영상·음악은 따로 켜야 같이 합쳐요. 한 번에 10,000개까지 합칠 수 있어요. 고른 파일은 먼저 같은 폴더의 숨김 사본(`.이름.ff-link`)으로 이름을 바꾸고, 링크를 만든 뒤 그 사본을 휴지통으로 보내요(중간에 실패하면 원래대로 돌려놓아요). 그래서 **휴지통을 비워야** 공간이 생기고, 사본을 휴지통에 넣지 못하면 숨김 파일로 남기고 위치를 알려 줘요. Windows 폴더 안의 파일은 합치지 않아요. 합친 뒤에는 두 경로가 한 파일이라 **한쪽을 고치면 다른 쪽도 같이 바뀌고**, 날짜·속성·권한도 남기는 파일의 것을 같이 써요. 따로 고쳐 쓸 문서·사진에는 쓰지 마세요. 진행 상황은 창과 작업 목록에 보이고(창을 닫아도 계속되고, 다시 열면 그 작업이 보여요. 끝날 때까지는 그 창에서 찾기·휴지통·합치기를 하지 않아요), 취소하면 파일 사이에서(내용을 다시 읽는 중이면 바로) 멈춰요. 이미 합친 파일은 합친 채로 남고, 합치던 파일은 마저 합치거나 손대지 않은 채로 멈춰요. 그때까지 휴지통으로 간 사본의 크기도 알려 줘요.
- **프로그램 정리**: 도구 메뉴(와 사이드바)의 "프로그램 정리…"는 설치된 프로그램(데스크톱 프로그램과 Microsoft Store 앱)을 크기와 마지막으로 쓴 때와 함께 보여 줘요. "오래 안 쓴 것"으로 6개월 넘게 안 쓴 프로그램만 볼 수 있고, "제거"는 그 프로그램의 공식 제거 프로그램을 실행해요(Microsoft Store 앱은 한 번 물은 뒤 제거 창 없이 바로, 앱 데이터와 함께 제거돼요). "남은 찌꺼기"는 지운 프로그램이 남긴 것으로 보이는 큰 폴더를 찾아요 (아래 "프로그램 정리").
- **도움말**: `F1`이나 툴바의 "?"로 기능 설명, 검색 문법, 문제 해결을 찾아볼 수 있어요. 버튼과 메뉴 항목에 마우스를 올리면 무엇을 하는지 짧게 보여요. 처음 켜면 4단계 안내가 한 번 나와요(도움말의 "처음 안내 다시 보기"로 다시 볼 수 있어요).
- **다른 드라이브로 옮기기**: 폴더의 메뉴에서 "다른 드라이브로 옮기기…"를 고르면, 폴더를 이 컴퓨터의 다른 로컬 NTFS 드라이브로 옮기고 원래 자리에 정션(링크)을 남겨요. 게임이나 캐시처럼 큰 폴더로 C: 드라이브 공간을 비울 때 쓰고, 프로그램은 예전 경로로 그대로 찾아가요. 진행률은 아래 작업 창에 보여요. 도구 메뉴의 "옮긴 폴더 목록…"에서 옮긴 폴더를 보고 원래 자리로 되돌릴 수 있어요. Windows·Program Files 같은 시스템 폴더와 드라이브 전체는 옮기지 않아요 (아래 "보안" 참고).
- **관리자 권한으로 보기**: 이 컴퓨터의 드라이브에서 내 계정으로 열 수 없는 폴더("액세스가 거부되었습니다")에는 "관리자 권한으로 보기" 버튼이 떠요(네트워크 위치, 연결한 네트워크 드라이브, SUBST 드라이브에는 뜨지 않아요. 관리자 권한으로 실행한 도우미는 그곳을 볼 수 없어서요). 다른 드라이브로 옮긴 폴더(정션) 안의 폴더도 볼 수 있어요. 누르면 UAC 창으로 한 번 허락을 받고, 그 폴더의 항목을 읽기 전용으로 보여 줘요("관리자 권한으로 읽는 중 (읽기 전용)"). 상세 정보 창에서도 읽을 수 없는 파일은 "관리자 권한으로 읽기"로 앞 256 KB를 텍스트나 16진수로 볼 수 있어요. 관리자 모드는 아래 상태 표시줄에 남은 시간과 함께 보이고, "끝내기"로 언제든 끌 수 있어요.
- **상세 정보 창**: Alt+P(Alt+Shift+P)나 툴바의 "상세 정보"로 고른 항목의 정보를 옆에 보여 줘요(v0.8까지의 "미리 보기 창"). 맨 위에 아이콘과 이름(폴더, 소리, 그 밖의 파일은 Windows 썸네일. 그림·동영상·PDF·텍스트는 아래 "미리 보기"에 그대로 보여서 종류 아이콘), 그 아래 종류·크기·파일 수(폴더)·수정한 날짜·위치(들어 있는 폴더, 옆 버튼으로 전체 경로 복사)·속성(숨김·시스템·링크)·스캔한 폴더에서 차지하는 비율, 그리고 "미리 보기"에 그림, 동영상, 소리, PDF, 텍스트(앞 256 KB, UTF-8·UTF-16·EUC-KR)를 열고, 나머지는 Windows 썸네일을 보여 줘요. 여러 개를 고르면 항목 수, 폴더·파일 수, 합계 크기를 보여 줘요. 원드라이브 같은 클라우드의 온라인 전용 파일은 읽지 않아요(조금만 읽어도 파일 전체를 내려받기 때문이에요). Windows에 이미 있는 썸네일만 보여 줘요. 경계선을 끌어 너비를 바꿀 수 있어요.
- **복사·이동**: Ctrl+C / Ctrl+X / Ctrl+V는 Windows 클립보드를 써서, 탐색기에서 복사한 파일을 여기에 붙여넣거나 그 반대로 할 수 있어요. 진행률·속도·남은 시간이 아래 작업 창에 보이고, 언제든 취소할 수 있어요. 잘라내서 붙여넣기를 마치면 클립보드를 비워서 같은 항목을 다시 옮기지 않아요. 작업이 도는 중에 창을 닫으면 먼저 물어요. 닫기로 하면 작업을 취소하고, 쓰다 만 복사본을 지운 뒤에 꺼져요.
- **이름이 같을 때**: 건너뛰기, 덮어쓰기, 이름 바꾸기("이름 (2)") 중에 골라요. 묻는 창에 양쪽이 파일인지 폴더인지(링크인지)와, 덮어쓰면 무엇이 휴지통으로 가는지 보여 줘요. "나머지에도 적용"으로 한 번에 정할 수 있어요. 덮어쓰기는 같은 종류끼리만 해요. 파일 위에 파일은 기존 파일을 휴지통으로 보내고, 폴더 위에 폴더는 탐색기처럼 안의 내용을 합치고, 안에서 이름이 같은 항목은 하나씩 다시 물어요("나머지에도 적용"을 골랐다면 같은 답을 써요). 파일·폴더·링크처럼 종류가 다르면 덮어쓰지 않아요. 묻는 창의 덮어쓰기가 꺼지고, "나머지에도 적용"으로 덮어쓰기를 골랐어도 그런 항목은 다시 물어요. 그래도 덮어쓰기로 답한 항목은 그대로 두고, 이유를 작업 창에 남겨요. 묻는 동안 창을 새로 고쳐서 묻는 창이 다시 뜨지 않으면, 작업 창에서 건너뛰기나 이름 바꾸기를 고를 수 있어요.
- **탐색기 기본 기능**: 뒤로/앞으로/위로, 주소창, 열기, 탐색기에서 보기, 새 폴더, 이름 바꾸기(F2), 휴지통으로 이동(Delete), 경로 복사.
- **정리 계획**: 폴더의 메뉴 "정리 계획 만들기 ▸"나 툴바의 "AI"(정리 도우미)에서 정리 후보(캐시·임시 파일), 중복 정리, 용량 줄이기(Windows 압축), 다른 드라이브로 옮기기 계획을 스캔 결과로 만들어요. AI 없이 동작해요. 계획은 할 일(단계) 목록으로 보여 주고, 직접 고르고 "실행"을 눌러야만 파일이 바뀌어요. 실행한 계획은 "되돌리기"로 거꾸로 되돌릴 수 있어요. 만든 계획은 툴바의 "계획"에 남아요 (아래 "AI 기능 (선택)" 참고).
- **업데이트**: 새 버전이 나오면 창 위쪽에 알려 주고, "지금 업데이트"를 눌러야만 설치해요(저절로 설치하지 않아요). 업데이트 파일은 서명을 확인한 뒤에만 설치하고, 설치할 때 UAC 창이 한 번 떠요 (아래 "설치와 업데이트").
- **안전**: 삭제는 항상 휴지통으로만 보내요. 영구 삭제 기능은 없어요(Windows 메뉴에서도 탐색기의 "삭제"와 "휴지통 비우기"는 빼 두었어요. 그 메뉴에서 고른 다른 명령은 예외로, 탐색기나 그 명령을 넣은 프로그램의 규칙을 따라요). 휴지통이 없는 드라이브(네트워크 드라이브, USB 메모리, 메모리 카드, SUBST 드라이브)에서는 지우지 않고 이유를 알려 줘요. 덮어쓰기도 원래 항목을 먼저 휴지통에 넣고, 휴지통에 넣을 수 없으면 덮어쓰지 않아요. 중복 파일을 하드 링크로 합칠 때도 원래 사본은 휴지통으로 보내고, 넣을 수 없으면 숨김 파일로 남겨 두고 알려 줘요. 다른 드라이브로 옮기기(이동, 폴더 옮기기와 그 되돌리기)만 원본을 휴지통 없이 지우는데, 복사본을 끝까지 확인한 뒤에만 지워요. 관리자 권한으로 보는 동안에는 아무것도 바꾸지 않아요.

AI 없이 모든 기능이 동작해요. AI(폴더·파일 설명, 구조·이름 정리 제안)는 직접 켜야 쓰는 선택 기능이고, 처음에는 꺼져 있어요 (아래 "AI 기능 (선택)").

## 설치와 업데이트

**처음 설치.** [Releases](../../releases)에서 `fine-file_<버전>_x64-setup.exe`를 받아 실행하세요.

- 설치 중에 **설치 폴더를 고를 수 있어요.** 기본값은 `C:\Program Files\fine-file`이고, 설치할 때 관리자 권한을 한 번 물어요.
- MFT 고속 스캔은 **Program Files 안에 설치했을 때만** 써요. 다른 폴더에 설치해도 앱은 그대로 쓸 수 있고, 스캔만 일반 탐색으로 해요 (아래 "보안" 참고).
- 아직 코드 서명이 없어서 SmartScreen 경고가 뜰 수 있어요. "추가 정보 → 실행"을 누르면 돼요.
- 같은 자리에 새 버전을 설치하면, 설치 프로그램이 끝에 Windows 아이콘 캐시를 새로 고쳐요(`ie4uinit.exe -show`, 셸에 아이콘이 바뀌었다고 알림). 그래도 작업 표시줄에 예전 아이콘이 보이면 아래 "문제 해결"을 보세요.

**업데이트.** v0.8부터는 새 버전을 앱 안에서 알려 줘요. 0.7.1 이하를 쓰고 있다면 v0.8.0만 위처럼 한 번 직접 받아 설치해 주세요(같은 자리에 설치하면 스캔 결과와 설정은 그대로예요). 그다음 버전부터는 앱이 알려 줘요.

- 새 버전이 나오면 창 위쪽에 "새 버전 … 나왔어요" 알림이 떠요. **알려 주기만 하고, 저절로 설치하지 않아요.** "바뀐 점 보기"(릴리스 노트, [CHANGELOG.md](CHANGELOG.md)의 그 버전 부분), "지금 업데이트", "나중에"(6시간쯤 뒤나 다음에 켤 때 다시 알려요. 그동안에도 왼쪽 "업데이트"에 "새 버전"이 보여요), "이 버전 건너뛰기"(그 버전은 다시 알리지 않고 "새 버전" 표시도 사라져요. 더 새 버전이 나오면 알려요) 중에 골라요.
- "지금 업데이트"를 누르면 무엇을 하는지 먼저 보여 주고, 업데이트 파일을 내려받아(크기와 %로 진행률이 보여요) **서명을 확인**해요. 내려받는 동안 "내려받기 취소"로 그만둘 수 있고, 1분 동안 하나도 받지 못하거나 15분이 지나도 다 받지 못하면 멈추고 알려 줘요. 앱에 들어 있는 공개 키와 맞지 않거나, 서명한 버전과 알린 버전이 다르면 설치하지 않아요("업데이트 파일의 서명이 맞지 않아 설치하지 않았어요"). 그래서 GitHub의 릴리스나 내려받는 길에서 누가 파일을 바꿔치기해도 설치되지 않아요.
- 모든 사용자용(Program Files) 설치라 **업데이트할 때마다 UAC 창이 한 번** 떠요. "예"를 누르면 앱이 꺼지고, 짧은 설치 창(진행 표시만)이 보인 뒤 새 버전이 저절로 다시 켜져요. 열어 둔 탭은 그대로 돌아와요. "아니요"를 누르면 설치하지 않고 앱이 다시 보여요(업데이트하려고 멈춘 작업은 그대로 멈춘 채예요, 아래).
- 설치 프로그램을 띄우기 전에 스캔 결과(캐시)를 저장해요. 복사·이동, 다른 드라이브로 옮기기, 중복 파일을 하드 링크로 합치기, 정리 계획의 실행·되돌리기가 도는 중이면 먼저 알려 주고(취소할 수 있어요), 그래도 업데이트하면 창을 닫을 때와 똑같이 멈춰요: 복사·이동은 취소하고 쓰다 만 복사본을 지우고, 하드 링크로 합치기는 합치던 파일을 마저 합치거나 손대지 않은 채로 멈추고, 계획은 하던 단계까지 마치고 되돌리기 기록을 남겨요. 작업은 UAC 창이 뜨기 전에 멈춰서, UAC 창에서 "아니요"를 눌러도 다시 이어지지 않아요. 알린 뒤 내려받는 동안 새로 시작한 작업(다른 복사·이동, 다른 계획)은 멈추지 않고 다시 물어요.
- 설치 프로그램은 같은 `fine-file.exe`로 도는 다른 창과 MCP 서버(`--mcp`)도 꺼요. 그래서 다른 창이 떠 있으면 먼저 알려 주고, 그 창에서 정리 계획이나 다른 드라이브로 옮기기가 도는 중이면 끝난 뒤에 하라고 해요. 다른 창의 복사·이동은 이 창에서 보이지 않으니, 그 창을 먼저 닫아 주세요.
- **언제 확인하나요**: "시작할 때 업데이트 확인"(처음에 켜져 있어요)을 켜 두면 앱을 켜고 15초쯤 뒤와, 켜 둔 동안 6시간마다 확인해요(창이 가려져 있으면 다시 보일 때까지 미뤄요). 왼쪽 **도구 → 업데이트**에서 지금 버전을 보고, "업데이트 확인"으로 바로 확인하고(건너뛴 버전도 다시 보여요), 자동 확인을 끌 수 있어요.
- **주고받는 것**: 확인할 때는 GitHub에서 최신 버전 정보(`releases/latest/download/latest.json`)를, 업데이트할 때는 설치파일을 받아 와요. 파일·폴더 정보는 보내지 않아요(보통의 웹 요청처럼 GitHub에는 IP 주소 같은 접속 정보가 남아요).

트리 보기에서 Ctrl+C / Ctrl+X는 트리에서 고른 줄에, Ctrl+V는 트리 맨 위 폴더에 쓰여요. 이름 바꾸기와 휴지통 이동은 목록·아이콘 보기에서 해요.

지도 보기에서는 마우스로 움직여요: 폴더 블록을 누르면 들어가고, 맨 위(가운데) 폴더를 누르면 위로 가요. 파일은 두 번 눌러 열어요. 가지 나무에서는 끌어서 움직이고, 휠로 확대·축소하고, +/−로 가지를 펴고 접어요("맞추기"는 전체를 다시 맞춰요). Backspace는 상위 폴더, Ctrl+V는 지금 폴더에 붙여넣기예요. 지도에는 고른 항목이 없어서 Shift+F10은 쉬어요.

중복 파일 찾기, 옮기기 같은 창이 열려 있는 동안에는 목록의 단축키(Delete, F2, Ctrl+A 등)와 탭 단축키가 쉬어요. Tab은 창 안에서만 돌아요.

관리자 권한으로 읽는 폴더에서는 F2, Delete, Ctrl+C / Ctrl+X / Ctrl+V, 새 폴더, Windows 메뉴, 끌어서 놓기가 동작하지 않아요 (읽기 전용).

## 스캔 방식

| 방식 | 어디서 | UAC 창 | 속도 | 비고 |
|---|---|---|---|---|
| MFT 고속 스캔 (전체 스캔) | 아직 스캔하지 않은 드라이브의 "스캔", 드라이브 버튼 옆 ▾ → "전체 다시 스캔 (관리자, 가장 정확)" | 떠요 (관리자 모드 중에는 안 떠요) | 수 초 | 로컬 NTFS. 보호된 폴더까지 전부 포함 |
| 빠른 동기화 | 스캔한 드라이브의 "동기화", 그리고 저절로(아래) | 없음 | 수 초~수십 초 | 열 수 없는 폴더는 지난 스캔 내용을 그대로 써요 |
| 일반 탐색 | ▾ → "일반 탐색으로 다시 스캔", FAT32·exFAT·네트워크 드라이브, UAC를 거절했을 때, Program Files 밖에 설치했을 때 | 없음 | 수 초~수십 초 | 열 수 없는 폴더는 빠짐 |

MFT 고속 스캔은 이 컴퓨터에 붙은 NTFS 드라이브(고정·이동식)에서만 시도해요. 네트워크 드라이브는 NTFS로 보여도 UAC 창 없이 바로 일반 탐색을 해요. ▾ 메뉴의 "전체 다시 스캔"은 그런 드라이브에서는 꺼져 있어요.

**UAC 창은 언제 뜨나요?** MFT를 읽는 전체 스캔에서만 떠요. 스캔 도우미는 결과를 보내고 바로 끝나서(관리자 권한을 계속 들고 있지 않으려고요) 전체 스캔을 할 때마다 다시 물어요. 그래서 v0.7부터 스캔한 드라이브의 버튼은 UAC 창이 없는 "동기화"이고, 전체 스캔은 ▾ 메뉴로 옮겼어요. 관리자 모드("관리자 권한으로 보기", 프로그램 정리의 "사용 기록 더 정확히 보기")가 켜져 있는 동안의 전체 스캔은 그 도우미가 MFT를 읽어서 다시 묻지 않아요 (아래 "보안"). 동기화, 실시간 반영, 일반 탐색, 검색, 둘러보기는 UAC 창 없이 돌아요.

**빠른 동기화.** 드라이브의 폴더를 일반 권한으로 다시 훑어서 지금 인덱스와 맞춰요. 없어진 항목은 빼고, 새 항목은 넣고, 바뀌지 않은 파일은 인덱스의 크기(디스크에서 차지하는 크기)를 그대로 써요. 내 계정으로 열 수 없는 폴더(보호된 폴더)는 마지막 스캔이 찾은 내용을 그대로 쓰고, 그런 폴더가 몇 개였는지 알려 줘요. 그래서 MFT 스캔을 동기화한 결과는 보호된 폴더까지 들어 있고(사이드바에 "동기화"로 보여요), 일반 탐색으로 만든 인덱스를 동기화하면 그대로 일반 탐색이에요.

- 동기화가 도는 동안 사이드바의 그 드라이브에 "동기화 중"(저절로 돈 것은 그 이유)이 보이고, 마치면 탭이 지금 보이는 것을 다시 읽어요. 인덱스는 그동안에도 그대로 쓸 수 있어요.
- 동기화한 결과도 캐시에 저장하지만, 비교에 쓰는 사본과 전 스캔(아래)은 바꾸지 않아요.
- 하드 링크가 여러 개인 파일은 바뀌지 않은 것으로 보이면 지난 스캔의 셈을 그대로 써요(WinSxS를 두 번 세지 않게요). 그래서 그런 파일이 지워져 크기가 어긋났을 때는 전체 스캔으로만 바로잡혀요.
- 전체 스캔을 시작하면 그 드라이브에서 돌던 동기화는 멈추고, 스캔 결과가 그 자리를 차지해요. 스캔이나 다른 동기화가 도는 드라이브는 동기화하지 않아요.

동기화가 저절로 도는 때 (이 컴퓨터의 고정·이동식 드라이브만, UAC 창 없이, 한 번에 하나씩):

- **앱을 켤 때**: 저장된 인덱스를 불러오고 5초쯤 뒤부터, 스캔한 드라이브를 하나씩 동기화해서 앱을 꺼 둔 동안 바뀐 것을 맞춰요. 켜기 전 10분 안에 인덱스가 디스크와 맞았던 드라이브(10분 안에 스캔하거나 동기화했거나, 실시간 반영이 놓친 것 없이 따라가던 중에 10분 안에 앱을 껐으면)는 바로 하지 않고 10분쯤 뒤에 동기화해요. 잠깐 껐다 켤 때마다 드라이브를 곧바로 다시 훑지 않으면서, 그 몇 분 사이에 바뀐 것도 맞추려고요(그 전에 "동기화"를 누르거나 스캔하면 그걸로 끝이에요). 앱을 끌 때 "놓친 것 없이 따라가던 중"으로 치는 드라이브는 이번에 켠 뒤 스캔이나 동기화를 한 번이라도 마친 드라이브뿐이라, 켜자마자 끄면 다음에 켤 때 다시 동기화해요. CPU와 디스크를 덜 쓰는 백그라운드 우선순위(스레드 4개)로 돌아요.
- **실시간 반영이 변경을 놓쳤을 때**: 30초쯤 뒤에 그 드라이브를 동기화해요. 계속 놓치는 드라이브는 적어도 10분 간격으로, 그 뒤로 놓칠 때마다 간격을 두 배씩(160분까지) 늘려요. 2시간 동안 조용하면 처음처럼 30초쯤 뒤부터예요. 화면 위 알림도 이 간격을 알려 줘요. 실시간 반영이 오류로 멈춰 있는 동안이나, 하드 링크 때문에 전체 스캔이 필요한 경우에는 저절로 동기화하지 않아요(오류로 멈췄으면 "동기화"를, 하드 링크 때문이면 ▾ → "전체 다시 스캔"을 눌러 주세요). 끊긴 변경 알림이 저절로 다시 이어지면 그때 그사이 놓친 변경을 저절로 동기화해요.
- 네트워크 드라이브는 저절로 동기화하지 않아요. "동기화"를 누르면 돼요.

정션·심볼릭 링크처럼 다른 곳을 가리키는 폴더는 따라 들어가지 않아요. 원드라이브 같은 클라우드 동기화 폴더는 안까지 세는데, 파일 크기는 내려받지 않은 파일도 원래 크기(논리 크기)로 세요. 일반 탐색은 아직 목록을 받아 오지 않은 클라우드 폴더를 열어 보기 때문에, 동기화 앱이 그 폴더의 목록을 내려받을 수 있어요.

**실시간 반영.** 스캔을 마쳤거나 저장된 인덱스를 불러온 로컬 드라이브(고정·이동식)는 Windows의 변경 알림(`ReadDirectoryChangesW`)으로 지켜봐요. 일반 권한으로 동작해서 UAC 창이 뜨지 않아요.

- 파일이나 폴더가 생기고, 지워지고, 크기·이름·위치가 바뀌면 0.3초쯤 모았다가 인덱스에 반영해요. 폴더 크기는 위쪽 폴더까지 모두 다시 합산되고, 검색에도 바로 나와요. 새로 생긴 폴더는 그 안을 한 번 훑어서 넣어요.
- 알림을 받는 버퍼는 로컬 드라이브마다 1 MiB예요(v0.6까지는 64 KB라, 쉬지 않고 쓰는 C:에서는 자주 넘쳤어요). 네트워크 드라이브는 Windows가 64 KB까지만 받아요.
- 압축 풀기, 대량 복사, Windows 업데이트처럼 변경이 한꺼번에 몰려 그래도 Windows가 알림을 다 담지 못하면, 그 드라이브에 "놓친 변경 있음"을 표시하고 화면 위에 알려 줘요. 인덱스는 그대로 쓸 수 있고 그 뒤의 변경도 계속 반영돼요. 놓친 변경은 빠른 동기화가 저절로 맞춰요. 처음에는 30초쯤 뒤지만, 계속 놓치는 드라이브는 간격이 10분부터 2시간 40분까지 길어지고 화면 위 알림에도 그렇게 적혀 있어요(위 "빠른 동기화"). 기다리지 않으려면 알림의 "동기화"를 누르면 돼요.
- 하드 링크가 여러 개인 파일이 지워졌을 때는 폴더 크기가 실제와 다를 수 있어서, 전체 스캔을 하라고 알려 줘요. 사이드바에는 "전체 스캔 필요"로 보여요. 동기화로는 바로잡히지 않아서(위 "빠른 동기화"), 동기화한 뒤에도 전체 스캔을 마칠 때까지 알림과 표시가 남아요. 앱을 다시 켜면 이 표시는 남지 않으니, 그 전에 전체 스캔을 해 주세요.
- 네트워크 드라이브는 지켜보지 않아요. 바뀐 내용은 "동기화"를 누르면 보여요.
- 앱을 끈 동안 바뀐 내용은 다음에 켤 때 빠른 동기화로 맞춰요. 끈 지 10분이 안 돼서 다시 켰으면 바로 하지 않고 10분쯤 뒤에 맞춰요(위 "빠른 동기화"). 그동안에는 저장된 인덱스를 그대로 보여 줘요. 바로 맞추려면 "동기화"를 누르면 돼요.
- USB 드라이브를 "안전하게 제거"하거나 포맷하려고 하면 지켜보기를 멈추고 드라이브를 놓아줘요.
- 반영된 변경은 1분 동안 새 변경이 없을 때(같은 드라이브는 10분에 한 번까지, 계속 바뀌는 드라이브는 30분마다)와 앱을 끌 때 캐시 파일에 저장해요. 캐시가 저장되는 앱 데이터 폴더 안의 변경은 반영하지 않아요.

스캔 결과는 `%LOCALAPPDATA%\com.toxh13.fine-file\index\`에 저장돼서, 다음에 켜면 바로 보여요. 이름 바꾸기, 휴지통 이동, 실시간으로 반영된 변경도 이 파일에 다시 저장돼요. "지난 스캔과 비교"에 쓰려고, 스캔을 마치면 실시간 반영이 들어가기 전의 결과를 `<드라이브 문자>.scan.idx`(어느 디스크에서 만들었는지는 `.scan.vol`)로 따로 남겨 두고, 드라이브를 다시 스캔할 때 이 사본을 전 스캔 `<드라이브 문자>.prev.idx`(`.prev.vol`)로 바꿔요. 그래서 전 스캔에는 실시간 반영, 이름 바꾸기, 휴지통 이동이 들어가지 않고, 스캔한 드라이브마다 디스크를 캐시 크기의 두 배까지 더 써요(전 스캔과 이번 스캔의 사본. NTFS에서는 사본이 캐시와 같은 파일(하드 링크)이라, 실시간 반영으로 캐시를 처음 다시 저장할 때까지는 자리를 따로 차지하지 않아요). 디스크가 거의 차 있으면 사본을 만들지 않고, 캐시를 저장할 자리가 모자라면 사본을, 그래도 모자라면 전 스캔을 지운 뒤 다시 저장해 봐요. 그러면 비교할 때 "디스크 공간이 부족해서 이전 스캔을 남겨 두지 못했어요"라고 알려 줘요. 다른 디스크에서 만든 전 스캔은 비교하지 않아요. 비교를 보면 그 드라이브의 전 스캔을 메모리에 올려 두어서 그 드라이브가 쓰는 메모리가 두 배쯤 되고, 5분 동안 비교하지 않으면 내려놔요(다시 비교하면 다시 읽어요). 제거할 때 "앱 데이터 삭제"를 고르면 제거를 실행한 계정의 이 폴더가 지워져요. 다른 계정의 캐시나, 다른 관리자 계정의 암호로 제거를 허락했을 때 내 계정의 캐시는 남으니 직접 지우면 돼요. 캐시에는 어느 디스크에서 만들었는지도 함께 저장돼서, 같은 드라이브 문자에 다른 디스크를 꽂으면 그 캐시는 쓰지 않아요. 예전 버전이 쓰던 `%LOCALAPPDATA%\fine-file\`은 처음 켤 때 새 위치로 옮겨요.

## 프로그램 정리

도구 ▾ → "프로그램 정리…"(사이드바의 "프로그램 정리"도 같아요)는 안 쓰면서 자리만 차지하는 프로그램을 찾아 지우는 걸 도와요. 탭이 두 개예요.

**설치된 프로그램**

- **목록**: Windows에 등록된 프로그램(Uninstall 레지스트리: 모든 사용자용 64비트·32비트, 내 계정)과 Microsoft Store 앱이에요. 시스템 구성 요소, 업데이트, 프레임워크, Windows 자체 패키지는 빼요. 큰 것부터 보여 주고, 이름·게시자로 찾을 수 있어요.
- **크기**: "스캔 기준"은 스캔한 드라이브에서 설치 폴더를 인덱스로 잰 값, "프로그램이 알려 준 값"은 설치할 때 레지스트리에 적어 둔 값이라 실제와 다를 수 있어요. 둘 다 없으면 "크기 모름"이에요. 디스크를 따로 훑지 않아요. 드라이브 전체, Program Files 자체, AppData처럼 여러 프로그램이 같이 쓰는 폴더는 어느 프로그램의 크기로도 세지 않아요.
- **마지막 사용**: 시작 메뉴·작업 표시줄·바탕 화면·탐색기에서 실행할 때 Windows가 남기는 기록(UserAssist, 실행 횟수도 있어요)으로 짐작해요. 다른 프로그램이 띄운 실행은 남지 않아서 실제보다 오래돼 보일 수 있어요. **"사용 기록 더 정확히 보기 (관리자)"**는 관리자 모드를 켜고(UAC 창 한 번) Windows 미리 읽기 기록(Prefetch, 어떻게 실행했든 남아요)의 파일 이름과 시각을 읽어서 더 최근 것을 써요. 둘 다 없을 때만, Windows가 그 시각을 기록하게 돼 있으면 실행 파일을 마지막으로 연 시각을 써요. 칸에 마우스를 올리면 근거가 보여요. "새로 고침"은 관리자 모드가 아직 켜져 있을 때만 Prefetch를 다시 읽어요(새 UAC 창은 띄우지 않아요).
- **오래 안 쓴 것**: 6개월 넘게 쓰지 않았거나, 쓴 기록 없이 6개월보다 전에 설치한 프로그램만 보여요.
- **제거**: 한 번 물은 뒤, 그 프로그램이 Windows에 등록한 공식 제거 명령(`UninstallString`)을 그대로 실행해요. 따로 등록된 "묻지 않고 지우는 명령"(`QuietUninstallString`)은 쓰지 않지만, 등록된 제거 명령이 원래 조용한 프로그램도 있어요. 그런 프로그램(Slack처럼 Squirrel로 설치된 앱, 제거 명령에 `/S`·`/silent` 같은 옵션이 붙은 프로그램)은 제거 창 없이 바로 지워져요. 대부분은 제거 프로그램의 창이 떠서 그 창에서 한 번 더 물어요. Windows Installer 프로그램은 `msiexec /X{제품 코드}`로 실행하고, 모든 사용자용 프로그램은 제거 프로그램이 UAC 창을 띄울 수 있어요. 실행하기 전에 레지스트리를 다시 읽어 그 항목이 그대로인지 확인해요. Store 앱은 이 계정에서 `Remove-AppxPackage`로 제거해요(Windows가 제거할 수 없게 한 앱은 제거 버튼이 꺼져 있어요). **Store 앱에는 제거 프로그램 창이 없어서, 묻는 창에서 "제거"를 누르면 더 묻지 않고 바로 제거되고, 앱이 저장해 둔 데이터도 함께 지워져요(휴지통으로 가지 않아요).** 그래서 그 창은 "취소"에 먼저 커서가 가 있어요. 다른 계정의 앱은 그대로고, Microsoft Store에서 다시 설치할 수 있지만 데이터는 돌아오지 않아요. **fine-file이 프로그램 파일을 직접 지우지는 않아요.** 제거가 끝나면 "새로 고침"으로 목록을 다시 읽어요.

**남은 찌꺼기**

- 지운 프로그램이 남긴 것으로 보이는 50 MB 이상의 폴더를 찾아요. Program Files(64비트·32비트), ProgramData, AppData(Local, Roaming), `AppData\Local\Programs` 바로 아래 폴더 중에, 지금 설치된 프로그램(시스템 구성 요소와 업데이트까지)의 이름·게시자·폴더·실행 파일과 이어지지 않는 것이에요. Windows·Microsoft 폴더, 여러 프로그램이 같이 쓰는 폴더, 개발 도구의 캐시, 그 회사의 프로그램이 설치돼 있는 드라이버 회사 폴더는 빼요. 소리·터치패드·네트워크·지문 인식 드라이버가 옆에 두는 폴더(Intel, Realtek, Waves·MaxxAudio, Dolby, DTS, Nahimic, Conexant, Synaptics, ELAN, Alps, Goodix, Killer·Rivet Networks, Qualcomm, Broadcom, MediaTek 등)는 늘 빼요. 이런 드라이버는 Windows 업데이트나 PC 제조사가 깔아서 프로그램 목록에 없는 게 보통이고, 그 폴더를 지우면 장치의 부가 기능이 망가져요. 스캔한 드라이브에서만, 인덱스로 찾아요.
- 모두 "주의"이고, 지난 30일 안에 바뀐 실행 파일·DLL이 들어 있거나, 그 회사의 프로그램이 없는 드라이버 회사(NVIDIA·AMD) 폴더면 "위험"이에요. "위치 보기"로 폴더를 열어 안을 확인할 수 있어요.
- **지우는 방법**: "위치 보기"로 폴더를 열어 안을 확인하고, 위로(Backspace) 가서 그 폴더를 고른 뒤 Delete(휴지통)로 지워요. 이 앱은 일반 권한으로 돌아서, 관리자만 바꿀 수 있는 폴더(Program Files 안의 폴더, ProgramData의 일부 폴더)는 Delete로도 지워지지 않고 이유를 알려 줘요. 그런 폴더는 오른쪽 클릭 → "탐색기에서 보기"로 열어 탐색기에서 지워 주세요(탐색기의 규칙과 UAC 창을 따라요).
- "정리 계획 만들기"는 고른 폴더를 **정리 계획**(휴지통으로 보내는 단계)으로 남겨요. 계획은 다른 계획과 똑같은 안전 규칙으로 확인돼요(아래 "정리 계획"). **지금 규칙은 Program Files, ProgramData, AppData 안의 항목(캐시 말고)을 계획에서 건드리지 않아서, 남은 찌꺼기 계획의 단계는 이유와 함께 "건너뜀"으로 저장되고 실행되지 않아요.** 그래서 계획은 무엇이 남았는지 정리한 목록으로 쓰고, 만든 뒤에도 프로그램 정리 창은 그대로예요(알림의 "계획 열기"로 볼 수 있어요). 실행할 수 있는 단계가 하나라도 있으면 계획 창이 열리고, 그 단계는 처음에 골라 두지 않았어요. 앱 안의 설명(프로그램 정리 창, 도움말)도 같은 내용이에요.

## AI 기능 (선택)

AI는 켜야만 쓰는 선택 기능이에요. 처음에는 꺼져 있고, 꺼진 채로도 앱의 모든 기능과 규칙으로 만드는 정리 계획이 그대로 동작해요.

- **어디서 쓰나요**: 툴바의 "AI"는 정리 도우미(지금 폴더의 AI 설명, 규칙·AI로 계획 만들기)를 열어요. 오른쪽 클릭 메뉴의 "AI로 설명…"은 그 폴더나 파일을, "정리 계획 만들기 ▸"는 그 폴더의 계획을 만들어요. 톱니바퀴 버튼은 AI 설정, "계획"은 정리 계획 목록이에요. "계획"의 숫자는 Claude 앱이 MCP로 제안해서 확인을 기다리는 계획 수예요.
- **AI로 하는 것**: 폴더·파일 설명(무엇인지, 어느 프로그램 것인지, 지워도 되는지, 지우면 프로그램이 다시 만드는지), 구조 정리 계획(하위 폴더를 만들고 나눠 옮기기), 이름 정리 계획(이름을 한 가지 규칙으로 맞추기). AI가 낸 계획도 아래 "정리 계획"의 규칙을 똑같이 따라요.
- **답 보기**: AI의 설명은 제목·목록·굵게·코드·표 같은 서식(마크다운)을 살려 글로 보여 줘요. 앱이 직접 화면 요소로 만들어서 답 속의 HTML은 글자 그대로 보이고, 링크는 누를 수 없는 글자로(주소도 함께) 보여 주고, 그림은 불러오지 않아요. CLI가 덧붙이는 색 코드, "tokens used" 같은 줄, 답 전체를 감싼 코드 블록(글 하나만 든 JSON이면 그 글)은 빼요. 다른 값도 든 JSON은 빠뜨리는 것 없이 코드 블록 그대로 보여요. 경로와 파일 이름(`C:\proj\__init__.py`, `D:\사진\_정리_\IMG_0001.jpg`, `[최종](수정).hwp`)은 서식으로 읽지 않고 적힌 그대로 보여요. 계획 창의 AI 설명과 AI·MCP가 쓴 단계의 이유도 같아요. 규칙으로 만든 계획의 설명·이유와 앱이 덧붙인 줄("올바르지 않아서 뺀 단계…")은 서식 없이 글자 그대로 보여요.
- **AI가 꺼져 있으면**: AI 버튼과 메뉴는 켜는 방법을 알려 주고 AI 설정을 열어요. 규칙으로 만드는 계획(정리 후보, 중복 정리, 용량 줄이기, 다른 드라이브로 옮기기)은 늘 쓸 수 있어요.

### 보내는 정보

- **앱은 메타데이터만 보내요.** 경로, 이름, 종류(파일·폴더·링크), 크기, 파일 수, 수정일, 분류(시스템·프로그램·캐시…), 숨김·시스템 속성이에요. **앱이 파일 내용을 읽어 보내지는 않아요.** (Codex CLI는 아래 주의)
- 폴더는 그 폴더의 합계와 바로 아래 항목 중 큰 것 60개, 가장 큰 하위 폴더 10개의 안(2단계)까지예요. 스캔하지 않은 폴더는 지금 디스크에서 읽은 목록을 보내요(폴더 크기는 "?"로). 많아야 12,000자예요.
- **보내기 전에 미리 보기** (AI 설정, 처음에 켜져 있어요): 앱이 보낼 내용을 글자 그대로 보여 주고, "보내기"를 눌러야 보내요. 켜져 있는지는 물을 때마다 저장된 설정을 다시 읽어서 정해요(다른 창에서 켠 것도 따라요).
  - "보내기"를 누르면 보낼 내용을 다시 만들어 보여 준 것과 비교해요. 그사이 폴더에 항목이 생기거나 없어졌거나 다른 AI를 골랐으면 보내지 않고, 바뀐 내용을 다시 보여 줘요.
  - 보내는 순간에도 앱이 한 번 더 확인해요. 요청을 보내려고 다시 만든 내용이 글자 하나까지 같고 같은 AI로 지난 30분 안에 미리 보여 준 것일 때만 보내요. 그 틈에 바뀌었으면 아무것도 보내지 않고, 다시 미리 보고 보내 달라고 알려 줘요. 그래서 보내는 내용은 늘 미리 본 그대로예요.
- 보내는 곳은 AI 설정에서 고른 곳 하나뿐이에요. 이 앱이 따로 모으거나 다른 곳으로 보내는 정보는 없어요(업데이트 확인은 GitHub에서 최신 버전 정보만 받아 와요, 위 "설치와 업데이트").
- **Codex CLI 주의**: Codex는 명령 실행 같은 도구를 스스로 쓰는 에이전트예요.
  - 앱은 Codex를 내 `~/.codex/config.toml` 없이 실행해요(`--ignore-user-config`, `-c mcp_servers={}`). 그래서 거기 넣어 둔 MCP 서버·플러그인·프로필·직접 넣은 모델 공급자(`model_provider`)·모델 설정을 쓰지 않아요. 직접 넣은 공급자로만 Codex를 쓰고 있었다면 실패하거나 기본 공급자(OpenAI)로 갈 수 있어요. 모델은 AI 설정에서 고른 것을 써요.
  - 셸 명령, 웹 검색, 이미지·브라우저·컴퓨터 사용 같은 도구 기능도 끄고, 남는 것은 승인을 묻지 않는 읽기 전용 샌드박스에서 돌게 해요. 그래도 Codex가 가진 도구를 앱이 모두 끈다고 보장할 수는 없어요.
  - 그래서 Codex가 읽기 전용 샌드박스 안에서 이 PC의 파일을 읽고 그 내용을 OpenAI로 보낼 수 있다고 보고 써 주세요. 미리 보기는 앱이 넘기는 내용만 보여 줘요.
  - Claude Code CLI는 도구와 MCP 서버를 모두 끄고 실행해요.
- CLI(Claude Code, Codex)에는 보낼 내용을 명령줄이 아니라 표준 입력으로 넘겨요. 파일 이름이 다른 프로그램이 볼 수 있는 명령줄에 남지 않아요.
- 파일 이름은 AI에게 데이터일 뿐이라고 알리고, 이름 속에 지시처럼 보이는 글이 있어도 따르지 않게 해요. 그래도 AI의 답은 믿지 않는 데이터로 다뤄서, 계획은 아래 규칙으로 다시 확인해요.

### 키는 어디에 저장하나요

- API 키(Claude, OpenAI, jev)는 **Windows 자격 증명 관리자**(제어판 → 자격 증명 관리자 → Windows 자격 증명)에 `fine-file` 이름으로 저장해요. 파일, 로그, 오류 메시지에는 남기지 않고, 저장한 키는 화면에 다시 보여 주지 않아요. 서버가 오류 메시지에 키를 되돌려 보내도 가려서 보여 줘요.
- 나머지 설정(고른 AI, 모델, 주소, 미리 보기)은 `%LOCALAPPDATA%\com.toxh13.fine-file\ai.json`에 저장해요. 키는 들어 있지 않아요.
- 키를 지우려면 AI 설정에서 키 옆의 "지우기"를 누르거나, 자격 증명 관리자에서 직접 지우면 돼요.

### 요금과 구독

- API 키로 보낸 요청은 그 회사가 쓴 만큼 **키 주인에게** 청구해요. 이 앱은 요금을 받지 않고, 앱에 들어 있는 키도 없어요. 각자 자기 키를 넣어 써요.
- Ollama는 내 PC에서 돌아서 요금이 없어요.
- **Claude Pro·Max나 ChatGPT 같은 구독은 이 앱 안에서 쓸 수 없어요.** 이 앱은 구독 로그인을 받지도, 로그인 정보를 읽지도 않아요. Anthropic 약관은 다른 회사 앱이 Claude.ai 로그인을 제공하거나 구독 자격 증명으로 요청을 대신 보내는 것을 허용하지 않아요. 구독으로 쓰려면 두 가지가 있어요.
  - **MCP (권장)**: Claude 앱(Claude Desktop, Claude Code)에 fine-file을 MCP 서버로 붙여요(아래). 연결하는 쪽이 내 Claude 앱이라 이 앱은 구독 정보를 만지지 않아요.
  - **내 CLI 로그인**: 내가 직접 설치하고 로그인한 Claude Code CLI나 Codex CLI를 AI로 고르면, 내 PC에서 내 작업에 그 CLI를 불러 써요(개인 자동화). 앱은 CLI의 로그인 정보(`~/.claude`, `auth.json`)를 읽지 않아요. 사용량은 그 계정의 한도를 따르고, 개인적인 보통 사용을 넘는 용도는 각 회사 약관을 확인해 주세요. Claude Code를 다른 프로그램에서 부르는 경우의 조건은 약관 원문만으로 판단하기 어려운 부분이 있어요.
- 자세한 약관 조사는 [docs/research/market-and-license.md](docs/research/market-and-license.md)의 "3.5 AI 연결 방식별 공개 가능성"에 있어요.

### jev 위험도

**jev는 어디에 쓰나요?** 항목마다 "지워도 되는지"(안전·주의·위험)와 프로그램이 다시 만드는 항목인지를 빠르게 판정해 주는 서비스예요. 위의 AI(Claude, OpenAI 등)와는 따로라서, AI를 꺼 둔 채로 jev만 쓸 수도 있어요. 이 앱에서는 두 곳에 써요.

| 어디 | 하는 일 |
|---|---|
| 목록의 "위험도" 열 | 목록 보기 툴바의 "위험도"를 켜면, 그 탭에 보이는 항목마다 jev의 판정이 배지로 붙어요 |
| 정리 계획의 2차 확인 | 계획 창의 "jev로 위험도 다시 확인 (빠르고 저렴한 2차 판정)"을 누르면, 계획(규칙이나 AI)이 매긴 위험 옆에 jev의 판정이 "jev 안전"처럼 한 번 더 붙어요. 계획을 만든 쪽과 따로 보는 2차 의견이에요 |

- **필요한 것**: 내 jev API 키. 키가 없으면 버튼과 열이 생기지 않아요.
- **요금**: 보낸 만큼 jev 키 주인에게 jev의 조건대로 청구돼요. 이 앱은 요금을 받지 않아요.
- **보내는 것**: 메타데이터(경로·이름·종류·크기·날짜·분류)만. 파일 내용은 보내지 않아요.
- 앱 안에서는 AI 설정의 jev 칸, 목록의 "위험도" 열 머리(마우스를 올리면), 계획 창의 버튼 옆 "?", 도움말의 "jev 위험도"에 같은 설명이 있어요.

- [TypeSafe](https://typesafe.ai)의 jev는 **얼리 액세스** 서비스예요. 항목마다 지워도 되는지(안전·주의·위험)와 프로그램이 다시 만드는 항목인지를 받아 와요. 내 jev API 키로만 동작하고, 항목의 경로·이름·종류·크기·날짜·분류만 보내요(파일 내용은 보내지 않아요). 질문과 항목 이름은 한국어 그대로(UTF-8) 보내요. 한국어 이름이 요청 본문에 그대로 들어가는지는 테스트로 확인했지만, 한국어 이름으로 실제 jev 서버에 보내 본 적은 없어서 jev가 한국어 이름을 얼마나 잘 판단하는지는 확인하지 않았어요.
- 켜기: AI 설정의 "위험도 배지 (TypeSafe jev)"를 켜고 jev 키를 저장해요. 그러면 계획 창의 "jev로 위험도 다시 확인"과, 목록 보기 툴바의 "위험도"(탭마다 따로) 버튼이 생겨요.
- 목록의 "위험도"를 켜면 그 탭의 목록에서 **보이는 항목만** 한 번에 200개까지 물어서 "위험도" 열에 배지를 붙여요. 스크롤하거나 다른 폴더로 가면 새로 보이는 항목을 물어요. 목록은 기다리지 않고, 답이 오는 대로 배지가 붙어요. 한 번 받은 답은 앱을 끌 때까지 기억해요. 오류가 나면 배지 없이 그대로 두고 잠시 뒤에 다시 물어요. 검색 결과와 관리자 권한으로 읽는 폴더에서는 묻지 않아요. "보내기 전에 미리 보기"가 켜져 있으면 켤 때 무엇을 보내는지 먼저 묻고, 앱을 다시 켜면 꺼진 채로 시작해요.
- Windows가 쓰는 시스템 위치는 jev의 답과 상관없이 "위험"으로 보여요. 배지는 참고용이고, 계획의 단계를 대신 고르지 않아요.
- jev의 서비스 계약(Master Customer Agreement)은 공개돼 있지 않아서, 결과를 공개하거나 다른 곳에 쓰기 전에 TypeSafe에 확인하는 게 좋아요 (조사 문서 3.5).

### MCP로 Claude 앱에 연결

`fine-file.exe --mcp`는 창 없이 MCP 서버(stdio, JSON-RPC)로 돌아요. Claude 앱이 이 서버를 실행해서, 이 앱이 스캔해 둔 결과(캐시 파일)를 **읽기 전용**으로 봐요. 이 앱이 켜져 있지 않아도 되고, API 키도 필요 없어요.

- 도구: `list_drives`(드라이브와 스캔 여부), `folder_summary`(폴더 합계와 큰 항목), `search`(이름 검색), `largest`(큰 항목), `size_map`(크기 지도), `propose_plan`(정리 계획 제안).
- `propose_plan`은 계획을 **초안으로 저장만** 해요. 아무것도 옮기거나 지우지 않고, 계획을 실행하지도 않아요. 들어온 초안은 툴바의 "계획"에 숫자로 보이고, 목록에 "확인 필요"로 표시돼요. 열어서 단계를 고르고 실행해야만 바뀌어요.
- MCP 계획은 새 폴더·옮기기·이름 바꾸기·휴지통만 쓸 수 있어요. 파일의 확장자를 바꾸는 옮기기·이름 바꾸기는 받지 않아요(여는 프로그램이 달라져서요). 휴지통 단계와 "위험"(danger)이라고 한 단계는 처음에 고르지 않은 채로 저장돼요. Windows·Program Files·AppData·ProgramData·게임 폴더 안의 항목, `C:\Users`와 각 프로필 폴더, 문서·다운로드 같은 기본 폴더 자체, 개발 폴더(node_modules, 빌드 결과물. 휴지통 단계만 예외)는 계획에 넣지 않아요. 계획의 폴더는 이 컴퓨터의 로컬 드라이브에 있어야 해요(네트워크·SUBST 드라이브는 안 돼요). 받은 계획은 앱이 아래 "정리 계획"의 안전 규칙으로 다시 확인해요.
- 스캔한 드라이브만 보여요. 앱에서 다시 스캔하면 다음 요청부터 새 결과를 읽어요.

Claude Desktop: `%APPDATA%\Claude\claude_desktop_config.json`에 넣고 Claude Desktop을 다시 켜요.

```json
{
  "mcpServers": {
    "fine-file": {
      "command": "C:\\Program Files\\fine-file\\fine-file.exe",
      "args": ["--mcp"]
    }
  }
}
```

Claude Code: 터미널에서 실행해요(모든 프로젝트에서 쓰려면 `--scope user`를 붙여요). 셸에서는 역슬래시 하나가 맞아요.

```
claude mcp add fine-file -- "C:\Program Files\fine-file\fine-file.exe" --mcp
```

다른 폴더에 설치했다면 경로를 그 폴더의 `fine-file.exe`로 바꿔 주세요. 같은 내용을 AI 설정 창에서 복사할 수도 있어요.

### 정리 계획

계획은 "어떤 항목을 어떻게 바꿀지"를 단계마다 적은 목록이에요. 만들기만 해서는 아무것도 바뀌지 않아요.

| 종류 | 만드는 곳 | 하는 일 |
|---|---|---|
| 정리 후보 | 규칙 (AI 없이) | 임시 폴더 안의 항목(앱 데이터 안에서 하루 넘은 것은 "안전"), 캐시 폴더("주의"), 다운로드 폴더에서 30일 넘은 설치 파일("안전")과 압축 파일("주의"), 1년 넘게 손대지 않은 1 GB 이상 파일("주의")을 휴지통으로 |
| 중복 정리 | 규칙 | 내용이 똑같은 1 MB 이상 파일 중 프로그램 폴더 밖의 가장 새 것 하나만 남기고 휴지통으로 (중복 파일 찾기와 같은 비교) |
| 용량 줄이기 | 규칙 | 16 MB 이상인 큰 로그·텍스트·BMP·TIFF 파일과 사용자 폴더 안의 실행 파일·DLL을 Windows 압축(WOF LZX, 안 되면 NTFS 압축)으로. 파일은 그대로 열리고, 되돌리면 압축이 풀려요. 이유에 줄어들 것으로 보이는 크기를 적어요 |
| 다른 드라이브로 옮기기 | 규칙 | 5 GB 이상인 폴더를 남은 공간이 가장 큰 다른 고정 NTFS 드라이브로 옮기고 원래 자리에 정션을 남겨요(들어가는 만큼만, 10개까지). "다른 드라이브로 옮기기"와 같은 작업이에요 |
| 구조 정리, 이름 정리 | AI | 새 폴더·옮기기·이름 바꾸기만 써요. 지우기는 제안받지 않아요 |
| MCP 제안 | Claude 앱 | 위 "MCP로 Claude 앱에 연결" |

**계획 창.** 맨 위에 동작별 개수(새 폴더, 옮기기, 이름 바꾸기, 휴지통, 압축, 다른 드라이브로)와 선택한 항목 크기, 예상 확보 용량을 카드로 보여 줘요. 단계는 항목이 든 폴더별로 묶여(계획 폴더 기준의 상대 경로, 접고 펼 수 있어요) "'보고서 (2).pdf'을(를) '2026-10 보고서.pdf'(으)로 이름 바꾸기", "'IMG_0001.jpg'을(를) '사진' 폴더로 옮기기", "새 폴더 '2024' 만들기"처럼 이름으로 된 문장으로 보이고, 이유는 그 아래에 작게 보여요. 전체 경로는 마우스를 올리거나 "경로"를 누르면 보여요. 폴더 머리의 체크 상자로 그 폴더의 단계를 한 번에 고를 수 있어요. 새 폴더·옮기기·이름 바꾸기가 든 계획(구조 정리, 이름 정리, MCP 제안)은 "정리 전 · 후 비교"로 폴더 구조를 나란히 볼 수 있어요. 디스크를 다시 읽지 않고 계획의 단계로만 그려서 계획이 다루는 항목과 그 위 폴더만 보이고, 정리 후에는 고른 단계만 반영하고 휴지통으로 갈 항목은 줄을 그어 보여 줘요. 단계는 실행할 때처럼 차례대로 읽어서, 앞 단계가 만들거나 옮겨 놓을 항목(새 폴더, 옮긴 폴더 안의 항목)은 정리 전에 없고, 건너뛴 단계(항목이 없거나 이름이 이미 있는 단계 등)는 넣지 않아요. 실행이나 되돌리기가 끝났는데 실패한 단계가 있으면 단계 목록으로 돌아가 그 폴더를 펼쳐 주고, 폴더 머리에 "실패 N개"가 붙어요. 단계마다 오류의 이유가 보여요.

규칙으로 만드는 계획은 스캔한 드라이브에서만 만들 수 있어요. 휴지통 단계는 "안전"만 처음에 골라져 있어요. 계획은 `%LOCALAPPDATA%\com.toxh13.fine-file\plans\`에 저장되고, 되돌리기 기록도 같은 파일에 들어가요.

**안전 규칙.** AI가 만든 계획이든 규칙으로 만든 계획이든 똑같이 적용돼요.

1. **승인하기 전에는 실행하지 않아요.** 계획 창에서 단계를 확인하고 고른 뒤 "실행…"을 누르면, 동작별 개수(휴지통은 빨간색)를 보여 주고 한 번 더 물어요. "실행"을 눌러야 시작해요.
2. **단계마다 다시 확인해요.** 저장할 때, 고른 단계를 바꿀 때, 그리고 단계를 실행하기 바로 전에 다시 확인해서, 그사이 바뀌었거나 맞지 않는 단계는 실행하지 않고 이유를 남겨요.
   - 경로는 드라이브 문자로 시작하는 전체 경로이고 계획의 폴더 안이어야 해요(다른 드라이브로 옮길 곳과 중복 정리에서 남기는 파일만 예외). 드라이브 전체는 건드리지 않아요.
   - Windows·시스템 항목, Program Files 같은 설치 프로그램 폴더, 바탕 화면·문서·다운로드 같은 Windows 기본 폴더 자체는 건드리지 않아요(안의 항목은 돼요). 프로그램·게임·앱 데이터 폴더 안에서는 캐시를 휴지통으로 보내는 것과, "다른 드라이브로 옮기기"가 허락하는 폴더를 옮기는 것만 해요.
   - 정션·심볼릭 링크, 경로 중간의 링크, 원드라이브 같은 클라우드(온라인 전용) 항목, 시스템 속성 항목은 건드리지 않아요. 없어진 항목도 건너뛰어요.
   - 옮기기와 이름 바꾸기는 **이미 있는 이름 위에 쓰지 않아요**(덮어쓰지 않고 그 단계만 실패해요). 폴더를 그 폴더 안으로 옮기지 않고, 이름 바꾸기는 같은 폴더 안에서만 해요.
   - 압축은 NTFS 드라이브에서만, 다른 드라이브로 옮기기는 그 기능의 확인(권한, 클라우드 폴더, 남은 공간)을 모두 거친 뒤에만 해요.
3. **지우는 것은 휴지통으로만 보내요.** Delete 키와 같은 확인을 거쳐서, 휴지통이 없거나 꺼진 드라이브의 항목, 휴지통보다 큰 항목은 지우지 않아요.
4. **AI와 MCP의 계획은 믿지 않는 데이터로 다뤄요.** 모양이 맞지 않거나 위 규칙에 걸리는 단계는 이유와 함께 빼고(계획 설명에 적어요), 500단계까지만 받아요. AI·MCP가 제안한 휴지통 단계와 AI·MCP가 "위험"이라고 한 단계는 처음에 고르지 않은 상태라, 직접 확인하고 골라야 실행돼요. 파일 이름 속의 글은 지시로 받아들이지 않고, 이름 속의 방향 바꾸기 문자는 보이게 바꿔서 보여 줘요.
5. **되돌릴 수 있어요.** 실행한 단계마다 거꾸로 하는 방법을 기록해 두고, "되돌리기"는 마지막 단계부터 거꾸로 해요: 원래 이름으로, 원래 자리로 옮기기(그 자리에 다른 것이 생겼으면 되돌리지 않아요), 휴지통에서 바로 그 항목 되살리기, 압축 풀기, 옮긴 폴더를 원래 드라이브로 되돌리기, 계획이 만든 폴더는 비어 있을 때만 지우기. 휴지통을 비웠거나 휴지통에서 지운 항목은 되살릴 수 없어요. 되돌리지 못한 단계는 이유를 남기고, 다시 "되돌리기"를 누르면 남은 것만 다시 해 봐요.
6. **한 번에 하나만 실행해요.** 앱 창을 여러 개 띄워도 모든 창을 통틀어 하나예요. 실행 중인 계획은 지울 수 없어요.

계획을 실행하거나 되돌리는 동안 앱 창을 닫으려고 하면 먼저 물어요. 끄기로 하면 지금 하던 단계까지만 마치고(폴더 압축은 파일 사이에서 멈춰요) 그 단계의 되돌리기 기록을 저장한 뒤에 꺼져요. 다른 드라이브로 옮기는 중인 단계는 작업 창의 작업이라 취소되고, 원본은 그대로 남아요. 남은 단계는 실행하지 않고, 왜 하지 않았는지 이유를 남겨요(되돌리는 중이었다면 다시 "되돌리기"를 누르면 이어서 해요). 앱이 강제로 꺼지거나 컴퓨터가 멈췄을 때만 하던 단계가 되돌리기 기록에 빠질 수 있어요.

## 보안

**관리자 도우미.** MFT를 읽으려면 관리자 권한이 필요해서, 스캔할 때 `fine-file.exe --scan-helper C: <파이프 이름>`을 UAC로 한 번 더 실행해요.

- 도우미는 파일을 하나도 쓰거나 지우지 않아요. 앱이 만든 이름 있는 파이프(`\\.\pipe\fine-file-<pid>-<임의 16자리>`)로 결과만 보내고 끝나요. 캐시 파일은 일반 권한의 앱이 내 프로필에 저장해요. 그래서 표준 사용자가 다른 관리자 계정의 암호로 허락해도 결과가 엉뚱한 프로필에 저장되지 않아요.
- 파이프는 관리자 권한으로 실행된 프로세스만 열 수 있고, 같은 이름이 이미 있으면 만들지 않아요. 앱은 자기가 띄운 도우미 프로세스의 연결만 받아요. 도우미는 정해진 모양의 파이프 이름만 받고, 그 파이프를 만든 프로세스가 이름 속 pid와 같은지 확인해요. 앱 쪽이 도우미의 관리자 권한을 빌려 쓰지(impersonation) 못하게 막아요.
- 관리자 모드(아래 "관리자 모드 (읽기 전용)")가 켜져 있으면, 전체 스캔은 새 도우미를 띄우지 않고 이미 떠 있는 관리자 모드 도우미에게 MFT를 읽게 해요. 그래서 UAC 창이 다시 뜨지 않아요. 도우미는 결과를 같은 파이프로 1 MiB 조각씩 보내는데, 전체 크기를 먼저 알리고 끝에 빈 조각을 보내요. 앱은 받은 크기와 항목 수가 알린 것과 맞을 때만 결과로 써요. 중간에 끊기거나 맞지 않으면 그 결과를 버리고 관리자 모드를 끝낸 뒤, 예전처럼 UAC 창으로 스캔 도우미를 띄워요. 이때도 도우미는 아무것도 쓰거나 지우지 않고, 캐시는 일반 권한의 앱이 저장해요.
- 빠른 동기화는 관리자 권한을 쓰지 않아요. 도우미를 띄우지도, 관리자 모드 도우미에게 묻지도 않아요.

**설치 위치와 관리자 권한.** 관리자 도우미는 앱 자신(`fine-file.exe`)을 UAC로 다시 실행하는 방식이에요. 그래서 실행 파일이 내 계정으로 바꿀 수 있는 폴더(예: `%LOCALAPPDATA%\Programs`, `D:\Apps`)에 있으면, 내 계정으로 도는 악성 프로그램이 `fine-file.exe`나 옆의 DLL을 바꿔 둘 수 있어요. 다음 스캔 때 UAC 창(코드 서명 전이라 늘 "알 수 없는 게시자")을 허락하면 바뀐 코드가 관리자 권한으로 실행돼요.

- 그래서 앱은 **Program Files 안에서 실행될 때만** UAC를 요청해요. Program Files는 관리자만 바꿀 수 있는 폴더예요. 다른 곳에서 실행되면 UAC 없이 일반 탐색으로 스캔하고 그 이유를 알려 줘요. 관리자 모드(아래)도 같아서, 다른 곳에서 실행되면 켜지지 않고 이유를 알려 줘요.
- 설치파일은 "모든 사용자용"(Program Files) 설치만 해요.
- 개발 빌드(`target\debug`)는 이 제한에서 빠져요.
- 코드 서명은 이후 버전에서 추가할 예정이에요.

**휴지통.** 휴지통이 있는 드라이브라도 Windows가 휴지통에 넣지 못하는 경우가 있어요. 휴지통을 끈 드라이브("파일을 휴지통으로 이동하지 않고 바로 제거", 또는 같은 내용의 그룹 정책)와 휴지통 최대 크기보다 큰 항목이에요. 이런 항목은 지우지 않고 이유를 알려 줘요. 크기를 확인할 수 없거나 인덱스가 모르는 사이에 바뀐 항목(스캔하지 않은 폴더, 실시간 반영이 놓친 변경으로 커진 폴더, 휴지통 최대 크기가 기록돼 있지 않은 드라이브)은 Windows가 영구 삭제 전에 직접 확인 창을 띄워요. 거절하면 지우지 않아요.

**복사·이동.** 복사는 이미 있는 이름 위에 쓰지 않아요. 이름이 같으면 먼저 물어요.

- 덮어쓰기는 같은 종류끼리만 해요. 파일 위에 파일은 원래 파일을 휴지통으로 옮긴 뒤에 복사하고, 폴더 위에 폴더는 지우지 않고 합쳐요. 링크 위에 링크는 기존 링크만 휴지통으로 가고, 링크가 가리키는 곳은 그대로예요. 파일과 폴더, 정션·심볼릭 링크와 실제 파일·폴더처럼 종류가 다르면 덮어쓰지 않고 작업 창에 이유를 남겨요. 위의 휴지통 조건에 걸리는 항목(휴지통이 없거나 꺼진 드라이브, 휴지통보다 큰 항목)이나 원본이 들어 있는 폴더도 덮어쓰지 않고 작업 창에 이유를 남겨요.
- 파일은 같은 폴더 안의 숨긴 임시 이름(`.<이름>.ff-partial`)으로 복사하고, 끝까지 복사한 뒤에야 원래 이름으로 바꿔요(그 사이에 같은 이름이 생기면 다시 물어요). 그래서 앱이 강제로 꺼지거나 컴퓨터가 멈춰도, 쓰다 만 복사본이 다 된 파일처럼 보이지 않아요. 취소하거나 실패하면 그 작업이 만든 임시 파일만 지워요. 이미 있던 `.ff-partial` 파일(다른 작업 것이거나 강제 종료로 남은 것)은 건드리지 않고 다음 이름을 써요. 강제 종료로 남은 임시 파일은 직접 지우면 돼요.
- 같은 드라이브 안의 이동은 이름만 바꿔요. 다른 드라이브로 옮길 때는 항목 하나를 끝까지 복사하고, 복사본 크기가 원본과 같고 그동안 원본이 바뀌지 않았을 때만 원본을 지워요. 폴더는 비었을 때만 지워서, 건너뛰었거나 실패한 항목은 원래 자리에 남아요. 취소하면 하던 항목의 원본은 지우지 않고, 쓰다 만 복사본만 지워요.
- 작업이 도는 중에 창을 닫으면 먼저 물어요. 닫기로 하면 작업을 모두 취소하고, 쓰다 만 복사본을 지울 때까지 기다렸다가 꺼져요. 다 옮기지 못한 항목의 원본은 그대로 남아요.
- 정션·심볼릭 링크는 따라 들어가지 않고 링크 그대로 복사해요. 심볼릭 링크를 새로 만들려면 Windows 개발자 모드나 관리자 권한이 필요해요. 없으면 그 항목만 건너뛰고 이유를 알려 줘요.
- 폴더를 그 폴더 안으로 복사하거나 옮길 수는 없어요.

**다른 드라이브로 옮기기.** 폴더를 다른 드라이브로 옮기고 원래 자리에 정션을 남기는 작업이에요. 다른 드라이브로의 이동과 같은 규칙(이동 의미)을 따라서, 원본은 휴지통으로 가지 않고 복사본을 다 확인한 뒤에만 지워져요(휴지통에 넣으면 비우려던 드라이브에 같은 크기의 사본이 남기 때문이에요).

- 시작하기 전에 확인하는 것: 옮길 폴더의 이름을 바꾸고 그 자리에 정션을 만들 권한이 있는지(없으면 복사하기 전에 "옮길 권한이 없어요"라고 알려 줘요), 옮길 곳이 원드라이브 같은 클라우드 동기화 폴더 안이 아닌지(동기화 앱이 복사본을 클라우드에 올리거나 온라인 전용으로 바꿔서, 마지막 확인이 실패하고 그 복사본을 지우면 클라우드에서도 지워지기 때문이에요).
- 순서: 폴더 크기를 세고(이때 클라우드 항목이 있으면 멈춰요) → 옮길 드라이브에 폴더 크기보다 1 GB 넘게 남는지 확인하고 → 그 드라이브의 숨긴 임시 폴더(`.<이름>.ff-relocating`)로 복사하고 → 모든 항목의 위치·종류·크기·수정 시각을 원본과 비교하고 → 기록(`relocations.json`)에 "옮기는 중"으로 원본이 갈 이름과 복사본의 위치를 남기고 → 원본 이름을 `<이름>.ff-old`로 바꾸고(어떤 프로그램이 안의 파일을 쓰고 있으면 Windows가 거절해서, 쓰는 중인 폴더는 옮기지 않아요) 그사이 바뀐 것이 없는지 다시 확인하고 → 복사본에 원래 이름을 주고 → 원래 자리에 그 복사본을 가리키는 정션을 만들고 → 기록을 "옮김"으로 바꾼 뒤 → 마지막에 `<이름>.ff-old`를 지워요. 기록을 저장하지 못하면(옮기려는 드라이브가 꽉 찬 경우가 많아요) `.ff-old`를 지운 뒤 한 번 더 저장해 봐요.
- 원본 이름을 바꾼 뒤의 단계에서 실패하면 지금까지 한 일을 되돌려요(이름을 되돌리고, 만든 복사본과 "옮기는 중" 기록을 지워요). 취소는 원본을 다시 확인하는 단계까지 할 수 있고, 그 뒤로는 끝까지 진행해요.
- 링크(정션·심볼릭 링크)는 따라가지 않고 링크 그대로 옮겨요. 옮긴 폴더의 권한은 옮겨 간 드라이브의 폴더에서 이어받아요(탐색기로 복사할 때와 같아요).
- 옮기지 않는 것: 드라이브 전체, Windows, Program Files, System Volume Information, `$Recycle.Bin`, 앱 데이터 폴더와 그 안의 모든 것, ProgramData·사용자 폴더(`C:\Users\<이름>`) 같은 폴더 통째(그 안의 폴더는 옮길 수 있어요), 이런 폴더를 품은 폴더, 이미 링크인 폴더, 원드라이브 같은 클라우드 동기화 폴더의 항목(내려받아 둔 항목과 온라인 전용 파일 모두)이 든 폴더(옮기려면 모두 내려받아야 하고, 원래 자리에서 지우면 클라우드에서도 지워져서요. 되돌리기도 같아요). 옮길 곳은 이 컴퓨터의 다른 로컬 NTFS 드라이브여야 하고, 클라우드 동기화 폴더 안이면 안 되고, 같은 이름이 이미 있으면 옮기지 않아요.
- 한 번에 하나만 옮기거나 되돌려요. 앱 창을 여러 개 띄워도 모든 창을 통틀어 하나예요(앱 데이터 폴더의 `relocations.lock`을 잡아 둬요). 다른 창에서 옮기는 중인 폴더는 이 창의 "옮긴 폴더 목록"에 "링크 끊김"으로 보이지 않아요.
- 되돌리기("옮긴 폴더 목록…" → 되돌리기)는 같은 순서를 거꾸로 해요: 시작하기 전에 옮겨 둔 폴더와 정션의 이름을 바꾸거나 지울 권한이 있는지 확인하고(없으면 "되돌릴 권한이 없어요"), 옮겨 둔 폴더를 원래 드라이브의 숨긴 임시 폴더(`.<이름>.ff-restoring`)로 복사하고, 확인하고, 기록에 "되돌리는 중"으로 남기고, 옮겨 둔 폴더를 `<이름>.ff-old`로 바꿔 쓰는 중이 아닌지 확인한 뒤, 정션이 기록된 곳을 가리킬 때만 정션 자체를 지워요(정션이 가리키는 내용은 지우지 않아요). 그다음 복사본에 원래 이름을 주고, 기록을 "되돌림"으로 바꾸고, 옮겨 두었던 폴더를 지워요.
- 정션이 없어졌거나 다른 곳을 가리키거나 옮겨 둔 폴더가 없으면 목록에 "링크 끊김"으로 보이고, 되돌리기를 하지 않아요. 두 위치를 직접 확인해 주세요.
- 폴더가 새 자리에 간 뒤에 `<이름>.ff-old`를 다 지우지 못했거나 기록을 저장하지 못했으면, 옮기기(되돌리기)는 끝난 것이고 작업 창에 "완료 · 확인 필요"로 보여요. 알림에 무엇이 남았는지 나와요(기록을 한 번도 저장하지 못한 폴더는 "옮긴 폴더 목록"에서 되돌릴 수 없어서, 알림에 두 경로를 적어 줘요).
- **끝나지 않은 옮기기 정리.** 원본 이름을 바꾼 뒤에 앱이 강제로 꺼지거나 컴퓨터가 멈추면, 다음에 앱을 켤 때 "옮기는 중"·"되돌리는 중" 기록을 보고 마저 끝내거나 되돌려요. 정션이 이미 복사본을 가리키면 남은 `<이름>.ff-old`만 지우고 "옮김"으로 끝내고, 그 전에 멈췄으면 원본에 원래 이름을 돌려주고 복사본과 기록을 지워요. 되돌리기도 같아서, 복사본이 원래 이름을 받았으면 옮겨 두었던 폴더를 지우고 "되돌림"으로, 그 전이면 옮겨 둔 폴더와 정션을 되살리고 복사본을 지워 "옮김"으로 돌아가요. 폴더를 지우는 것은 그 폴더가 기록된 확인 결과(항목 수·크기·내용 요약)와 지금도 똑같을 때뿐이에요. 무엇을 해야 할지 알 수 없으면(그사이 같은 이름의 폴더가 새로 생겼거나, 내용이 달라졌거나, 다른 버전이 남긴 기록이라 비교할 수 없으면) 아무것도 지우거나 옮기지 않고 목록에 "링크 끊김"으로 보여 줘요. 두 위치(`<이름>.ff-old`, 숨긴 `.ff-relocating`·`.ff-restoring` 폴더 포함)를 직접 확인해 주세요. 정리하는 동안 새로 옮기거나 되돌리려고 하면 "지난번에 끝나지 않은 옮기기를 정리하는 중이에요"라고 알려 줘요.
- 앱이 복사본을 지우거나 `.ff-old`를 지우는 도중에 강제로 꺼지면 그 일부가 남을 수 있어요. 직접 지우면 돼요.

**관리자 모드 (읽기 전용).** 내 계정으로 열 수 없는 폴더와 파일을 보려고 "관리자 권한으로 보기"나 "관리자 권한으로 읽기"를 누르면, 앱이 `fine-file.exe --admin-helper <파이프 이름>`을 UAC로 한 번 실행해요.

- 도우미는 **읽기만 해요.** 폴더 목록과 파일 앞부분(최대 256 KB), 그리고 v0.7부터는 관리자 모드 중에 전체 스캔을 하면 그 드라이브의 MFT(위 "관리자 도우미")만 읽고, 파일을 쓰거나, 바꾸거나, 지우지 않아요. 프로그램 정리의 "사용 기록 더 정확히 보기"는 이 도우미로 `C:\Windows\Prefetch` 폴더의 목록(파일 이름과 시각)을 읽어요. 항목은 읽기 권한(또는 속성 읽기 권한)으로만 열고, 백업 권한(SeBackupPrivilege)을 켜서 권한 설정에 막힌 항목도 읽어요(켜지 못하면 상태 표시줄의 관리자 모드 옆에 일부는 열지 못할 수 있다고 보여 주고, 그 때문에 열지 못한 항목의 오류에도 덧붙여요). 이 컴퓨터의 드라이브 문자 경로만 받고, 장치·파이프·네트워크 경로는 받지 않아요. 네트워크 드라이브와 SUBST 드라이브(폴더에 드라이브 문자를 붙인 것)는 도우미가 도는 관리자 로그온 세션에 없어서 받지 않고, 화면에도 "관리자 권한으로 보기"를 띄우지 않아요. 열고 보니 이 컴퓨터의 드라이브가 아닌 곳이면(링크를 따라간 경우) 읽지 않고, 파일 링크는 내용을 읽지 않아요. 온라인 전용 클라우드 파일은 읽지 않아요(읽으면 내려받게 돼서요).
- **링크는 앱이 먼저 풀어요.** 경로 중간의 정션·심볼릭 링크(다른 드라이브로 옮긴 폴더도 정션이에요)는 일반 권한의 앱이 내 계정으로 먼저 따라가서, 링크가 가리키는 실제 경로를 도우미에게 보내요. 도우미는 그 경로의 폴더들을 연 채로 잡아 두어 그사이 이름이 바뀌거나 링크로 바뀌지 못하게 하고, 그래도 경로 중간에 링크가 있으면(폴더에 붙인 드라이브(볼륨)는 빼고) 열지 않아요. 열려는 항목 자체도 링크를 따라가지 않고 열어요. 도우미의 모든 열기는 익명(SECURITY_ANONYMOUS)이라, 링크를 거쳐 파이프나 다른 컴퓨터에 닿더라도 그쪽이 관리자 권한을 빌려 쓰지 못해요. Windows에 Redirection Guard가 있으면 켜서, 관리자가 아닌 사용자가 만든 정션은 아예 따라가지 않아요.
- 그래서 관리자 권한으로만 열 수 있는 폴더 안에 있는 링크는 관리자 모드에서 따라 들어가지 않아요("경로에 정션·심볼릭 링크가 있어서…", "관리자 모드는 일반 사용자 권한으로 만든 정션(링크)을 따라가지 않아요"). 링크가 가리키는 폴더로 가서 다시 열어 주세요. 원드라이브 같은 클라우드 폴더는 동기화 앱에 묻지 않고 이 컴퓨터에 있는 항목만 보여 줘요.
- 파이프 규칙은 스캔 도우미와 같아요: 관리자 권한으로 실행된 프로세스만 열 수 있고, 앱은 자기가 띄운 도우미의 연결만 받고, 도우미는 파이프를 만든 프로세스가 이름 속 pid와 같은지 확인해요. 도우미가 받는 것은 파이프 이름뿐이에요.
- 관리자 권한으로 읽는 폴더는 **읽기 전용**이에요. 화면에 "관리자 권한으로 읽는 중 (읽기 전용)"이라고 보이고, 이름 바꾸기, 휴지통, 잘라내기·복사·붙여넣기, 새 폴더를 할 수 없어요. 폴더 크기는 보이지 않아요.
- 관리자 모드는 **10분 동안 쓰지 않으면 저절로 꺼져요.** 쓸 때마다 다시 10분이에요. 상태 표시줄에 남은 시간이 보이고, "끝내기"로 바로 끌 수 있어요. 앱을 끄면 도우미도 끝나요. 관리자 모드가 켜져 있는 동안에는 열 수 없는 폴더를 열면 묻지 않고 관리자 권한으로 읽어요. 실시간 반영으로는 다시 읽지 않아서, 그 때문에 관리자 모드가 길어지지는 않아요(새로 고침(F5)하면 다시 읽어요).
- **Program Files 안에 설치했을 때만** 켜져요(위 "설치 위치와 관리자 권한"). 개발 빌드(`target\debug`)는 이 제한에서 빠져요.

## 문제 해결

앱 안의 도움말(`F1`) → "문제 해결"에도 같은 내용이 있어요.

**작업 표시줄 아이콘이 예전 것일 때.** Windows는 실행 파일의 경로마다 아이콘을 기억해 둬요(아이콘 캐시). 새 버전을 같은 자리(`C:\Program Files\fine-file`)에 설치하면 경로가 같아서 예전 아이콘이 한동안 남을 수 있어요. v0.7부터는 창이 작업 표시줄·Alt+Tab에 쓰는 큰 아이콘과 작은 아이콘을 모두 실행 파일의 아이콘으로 직접 정하고, 설치 프로그램이 끝에 아이콘 캐시를 새로 고쳐요. 그래도 예전 아이콘이면 차례로 해 보세요.

1. 컴퓨터를 한 번 다시 시작해요.
2. 작업 표시줄에 고정해 두었다면, 아이콘을 오른쪽 클릭 → "작업 표시줄에서 고정 해제"를 누르고 fine-file을 다시 실행한 뒤, 아이콘을 오른쪽 클릭 → "작업 표시줄에 고정"을 눌러요. 고정한 아이콘은 고정할 때의 그림을 따로 저장해 둬서 다시 고정해야 바뀌어요.
3. 시작 메뉴나 바탕 화면의 바로 가기도 지우고 다시 만들면 새 아이콘으로 바뀌어요.
4. 그래도 그대로면 명령 프롬프트(관리자 아님)에서 `ie4uinit.exe -show`를 실행해요. 내 계정의 아이콘 캐시를 다시 만들어요.

**"놓친 변경 있음"이 자주 보이거나 스캔을 자꾸 하라고 할 때.** v0.6까지는 C:처럼 쉬지 않고 쓰는 드라이브에서 변경 알림 버퍼(64 KB)가 자주 넘쳐 "다시 스캔 필요"가 떴고, 다시 스캔하면 UAC 창이 떴어요. v0.7부터는 버퍼가 1 MiB이고, 그래도 넘치면 빠른 동기화가 UAC 창 없이 저절로 맞춰요(위 "스캔 방식"). 처음에는 30초쯤 뒤지만, 계속 넘치는 드라이브는 컴퓨터를 덜 쓰려고 10분부터 2시간 40분까지 간격을 늘려서, 그동안 "놓친 변경 있음"이 남아 있을 수 있어요. 바로 맞추려면 "동기화"를 누르면 돼요. 앱을 꺼 둔 동안 바뀐 것도 켤 때 맞춰요(끈 지 10분이 안 됐으면 10분쯤 뒤에). 전체 스캔(▾ → "전체 다시 스캔")은 크기가 많이 어긋나 보이거나, "전체 스캔 필요"(하드 링크)가 보일 때만 하면 돼요.

**"실시간 반영 오류"(995)가 뜰 때.** 드라이브 목록 아래에 "실시간 반영 오류"가 뜨고 화면 위에 "변경 알림이 끊겼어요 (스레드 종료 또는 응용 프로그램 요청 때문에 I/O 작업이 취소되었습니다. (os error 995))"가 나오던 것은 v0.7.0까지 있던 버그예요. v0.7.1에서 고쳤어요. D:처럼 평소에 조용한 드라이브에서 주로 보였어요. 앱이 변경 알림을 처음 신청한 작업 스레드가 몇 초 쉬다가 끝나면 Windows가 그 스레드가 걸어 둔 신청을 취소했기 때문이에요(C:처럼 쉬지 않고 바뀌는 드라이브는 그 전에 다음 알림을 받아서 괜찮았어요). v0.7.1부터는 알림을 지켜보는 스레드가 모든 신청을 직접 해서 끊기지 않고, 그래도 알림이 끊기면("잠시 뒤 다시 이어 볼게요") 실시간 반영을 다시 이어 보고, 이어지면 그사이 놓친 변경은 빠른 동기화가 저절로 맞춰요. 다만 화면 위 알림에 "멈췄어요"라고 나오면(드라이브를 다시 열 수 없거나 알림이 계속 끊길 때) 저절로 다시 켜지지 않으니, 그 드라이브의 "동기화"나 다시 스캔을 눌러 주세요. 예전 버전에서 이 오류가 보였다면 새 버전을 설치해 주세요. 예전 버전에서는 "동기화"를 눌러도 잠시 뒤 다시 끊길 수 있어요.

**스캔할 때마다 UAC 창이 뜰 때.** UAC 창은 전체 스캔(MFT)에서만 떠요. 스캔한 드라이브는 "동기화"를 쓰면 UAC 창이 뜨지 않아요. 왜 매번 묻는지는 위 "UAC 창은 언제 뜨나요?"에 있어요.

## 개발

필요한 것: Rust (stable, MSVC), Node.js 20+, WebView2 (Windows 11 기본 포함)

```bash
npm install
npm run tauri dev      # 개발 실행
npm run tauri build    # 설치파일 빌드 → src-tauri/target/release/bundle/nsis/ (업데이트 서명 키가 필요해요, 아래)
```

`tauri.conf.json`이 업데이트 파일(`createUpdaterArtifacts`)도 만들게 돼 있어서, `npm run tauri build`는 서명 키(`TAURI_SIGNING_PRIVATE_KEY`)가 없으면 마지막 서명 단계에서 실패해요. 서명 없이 설치파일만 보려면 업데이트 파일을 끄는 설정 파일(`src-tauri/tauri.nosign.conf.json`)을 더해서 빌드해요. PowerShell, cmd, bash 어디서나 같아요(이 설치파일로는 앱 안의 업데이트를 할 수 없어요).

```bash
npm run tauri build -- --config src-tauri/tauri.nosign.conf.json
```

`--config`에 JSON을 바로 적는 방법(`'{"bundle":…}'`)은 Windows PowerShell 5.1이 안의 큰따옴표를 빼고 넘겨서 동작하지 않아요. 그래서 파일로 둬요.

테스트:

```bash
cd src-tauri
cargo test
# 실제 드라이브 스캔 확인 (MFT는 관리자 터미널에서)
FF_DRIVE=D: cargo test --release real_ -- --ignored --nocapture
```

GitHub Actions(`.github/workflows/ci.yml`)는 `main`에 푸시할 때와 풀 리퀘스트마다 Windows에서 `npm ci`, `npx tsc --noEmit`, `npx vite build`, `cargo test --release`, `cargo clippy --all-targets -- -D warnings`를 돌려요. 설치파일을 만들거나 릴리스하지 않아서 서명 키가 필요 없어요. Rust 버전은 `ci.yml`에 고정(지금 1.97.1)해 두어서, 새 Rust의 clippy가 더한 경고로 CI가 갑자기 깨지지 않아요. 올릴 때는 이 PC에서 `rustup update`를 하고 `cargo clippy --all-targets -- -D warnings`와 `cargo test`가 깨끗한지 본 뒤 `ci.yml`의 버전을 함께 바꿔요.

## 릴리스

릴리스는 업데이트 서명 키가 있는 이 PC에서만 만들어요. 서명 키는 GitHub에 올리지 않고(Actions의 secret에도 넣지 않아요), GitHub에는 설치파일, 그 서명(`.sig`), `latest.json`만 올라가요. 설치된 앱은 `latest.json`을 읽어 새 버전을 알리고, 내려받은 설치파일을 앱에 들어 있는 공개 키로 확인해요.

1. `package.json`, `package-lock.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`의 버전을 올리고, [CHANGELOG.md](CHANGELOG.md)에 `## [x.y.z] - 날짜` 부분을 써요. 이 부분이 릴리스 노트이자 앱의 "바뀐 점 보기"예요.
2. 커밋하고, 연습으로 한 번 돌려 봐요. 빌드하고 서명하고 `latest.json`을 써서 보여 주지만, 태그·푸시·릴리스는 하지 않아요(커밋하지 않은 변경이 있어도 돼요).

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\release.ps1 -Version x.y.z -DryRun
   ```

3. 실제로 릴리스해요. 버전이 네 파일(`package-lock.json`은 맨 위와 `packages[""]` 두 곳)에서 같은지, 커밋하지 않은 변경이 없는지, 같은 태그가 없는지, 태그를 올리면 GitHub에서 도는 워크플로(`on: push: tags`)가 저장소에 없는지, `gh`에 로그인했는지 확인한 뒤, 서명해서 빌드하고 `v<버전>` 태그를 만들어 브랜치와 태그를 올리고 GitHub 릴리스(설치파일, `.sig`, `latest.json`)를 만들어요.

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\release.ps1 -Version x.y.z
   ```

**서명 키를 꼭 백업하세요.** 키는 `%USERPROFILE%\.tauri\fine-file.key`(비밀번호 없음)이고, 공개 키는 `src-tauri/tauri.conf.json`의 `plugins.updater.pubkey`에 들어 있어요.

- 키를 잃어버리면 이미 설치된 앱에 보낼 업데이트에 서명할 수 없어요. 새 키를 만들면 그 키로 서명한 업데이트를 기존 앱이 받지 않아서, 모두가 새 버전을 직접 받아 다시 설치해야 해요.
- 키가 새면 누구든 진짜처럼 서명한 업데이트를 만들 수 있어요. 비밀번호가 없는 키라 파일만 있으면 돼요. 암호화한 USB나 비밀번호 관리자처럼 안전한 곳에 사본을 두고, 저장소·클라우드 동기화 폴더·메신저에는 두지 마세요.

버전마다 바뀐 점은 [CHANGELOG.md](CHANGELOG.md)에 있어요.

v0.7에서 바뀐 것 (v0.6을 써 본 의견에서):

- **스캔한 드라이브의 버튼이 "동기화"예요.** 관리자 권한 없이(UAC 창 없이) 다시 맞추고, 앱을 켤 때와 실시간 반영이 변경을 놓쳤을 때는 저절로 돌아요. MFT 전체 스캔은 드라이브 버튼 옆 ▾ 메뉴의 "전체 다시 스캔 (관리자, 가장 정확)"이에요. 일반 탐색으로 다시 스캔하는 것도 거기 있어요 (위 "스캔 방식").
- **UAC 창은 MFT 전체 스캔에서만** 떠요. 관리자 모드가 켜져 있으면 전체 스캔도 묻지 않아요.
- **변경 알림 버퍼가 1 MiB예요**(64 KB에서). C:처럼 쉬지 않고 쓰는 드라이브에서도 알림을 놓치는 일이 드물어요. "다시 스캔 필요" 대신 "놓친 변경 있음"이라고 보이고, 화면 위 알림은 저절로 다시 맞춘다고 알려 줘요(바로 하려면 "동기화").
- **프로그램 정리**: 설치된 프로그램의 크기와 마지막 사용, 공식 제거 프로그램으로 제거, 남은 폴더 찾기 (위 "프로그램 정리").
- **도움말**: `F1`이나 툴바의 "?", 사이드바의 "도움말". 버튼과 메뉴 항목마다 하는 일을 툴팁으로 보여 줘요. 처음 켜면 4단계 안내가 한 번 나와요.
- **작업 표시줄 아이콘**: 창의 큰 아이콘을 직접 정하고, 설치 프로그램이 아이콘 캐시를 새로 고쳐요 (위 "문제 해결").
- **실시간 반영 오류(995)**: D:처럼 조용한 드라이브에서 "변경 알림이 끊겼어요 (… os error 995)"로 실시간 반영이 자꾸 멈추던 버그를 고쳤어요 (위 "문제 해결").
- **AI 답 서식**: 설명이 명령줄 출력처럼 보이지 않게 제목·목록·굵게·표를 살려 보여 줘요 (위 "AI 기능 (선택)").
- **정리 계획 창**: 요약 카드, 폴더별로 묶은 문장형 단계, 구조·이름 정리의 "정리 전 · 후 비교" (위 "정리 계획").
- **jev**: 어디에 쓰는지 AI 설정, 목록의 "위험도" 열, 계획 창, 도움말에서 설명해요 (위 "jev 위험도").

남은 것: 코드 서명(위 "설치 위치와 관리자 권한"), 실행 파일의 디지털 서명·게시자 표시.
